---
title: "Claude 让记忆可编辑，生产 Agent 仍需要可治理的记忆层"
---

Claude 的记忆更新标志着 AI 产品的一项变化：记忆开始可见、分类、可编辑，并提供明确的敏感主题设置。这改善了用户控制，也提醒我们，生产 Agent 需要在模型内置记忆之外，建立可治理的记忆层。

助手的内置记忆帮助它在应用内保留背景。这里的可治理记忆层，是指明确规定保存什么、谁可以检索、如何更新和删除的服务。多用户或多租户应用还可能需要与这些边界对应的访问控制和变更历史。

Anthropic 的发布说明给出了具体变化。2026 年 7 月 10 日，Claude 记忆从每日摘要改为单独分类的条目，由 Claude 在对话中读取和更新。8 月 25 日，记忆扩展到云端 Chat 与 Cowork，用户可以按 Topics 编辑或删除；健康与信仰等内容在开启敏感主题前不被保留；Free、Pro 和 Max 默认开启，Team 与 Enterprise 组织默认关闭。这些都是实质控制。[Anthropic 发布说明](https://support.claude.com/en/articles/12138966-release-notes)记录了公开宣布的行为。

可编辑能力本身仍不足以构成可迁移的企业记忆层。生产系统可能同时使用多种模型、Agent 框架、工具、知识来源、身份系统和部署环境，需要在保留背景的同时，明确每段历史的使用范围和期限。因此，实现问题还包括：组织能否管理被记住状态的完整生命周期？

## 可编辑性为什么改变了讨论

过去，记忆常被当作后台机制：有效时有帮助，失效时难以检查。可编辑 Topics 改变了这种预期，承认了三个运行事实。

第一，记忆可能出错。偏好会改变，项目决策可能被推翻，自动摘要也可能丢失重要条件。编辑和删除使记忆可以纠正。

第二，记忆的敏感程度不同。Anthropic 的敏感主题设置说明，应用需要明确哪些信息可以长期保存，哪些需要额外同意，哪些应当排除。

第三，组织默认设置很重要。个人觉得有用的能力，在企业中仍需要管理员控制起点、明确归属，并提供检索遵循边界的证据。Team 与 Enterprise 的默认设置，说明记忆决策也属于组织管理。

这一方向有价值。生产系统还需要处理记忆跨 Agent 共享、连接工具，以及保留时间超过单次对话后产生的问题。

## 从产品功能走向可治理的数据层

这里的“可迁移”，意味着组织能够通过明确接口与策略，独立于某个聊天界面或模型运行环境管理记忆。当 Agent 更换、会话结束或模型供应商变化时，记忆边界与处理规则仍然清晰。

Oracle 的开发者指南区分了 RAG 与 Agent 记忆：RAG 检索文档或数据，为回答提供依据；记忆保存跨交互的有用状态。RAG 应保留来源证据，记忆则可在有效且获准的前提下，保留限定范围的偏好、决策、摘要、任务状态和工具结果。Oracle 还强调记忆应可纠正、可删除，作用域应使用明确的用户、租户、Agent 与会话标识。[Oracle Developers 的《Agent Memory Is Not RAG》](https://blogs.oracle.com/developers/agent-memory-is-not-rag)说明了这种区别及其运行影响。

这形成一条实际规则：

> 用 RAG 获取有来源依据的证据与当前知识；用持久记忆保存经过明确选择、仍有价值且允许召回的限定范围状态。

两者可以配合。Agent 准备客服回复时，通过 RAG 读取当前政策，从记忆中召回已批准的沟通偏好，再向实时系统查询订单状态。如果统一称为“上下文”，就容易忽略它们各自的更新、来源与授权规则。

## 添加持久记忆前，先定义什么

以下是应用设计的参考流程。实际采用时，需要核实所选产品提供哪些控制，以及应用负责哪些部分。

```text
对话或工具结果
        |
        v
决定保存什么
        |----> 丢弃、脱敏，或仅保留在本会话
        v
已存储记忆
（内容、归属、来源、时间、状态）
        |
        |----> 按应用规则更新或删除
        v
在调用者获准范围内检索
        |
        v
Agent 上下文
```

记录入口承担筛选职责。生产设计应区分临时观察、候选记忆与已批准的持久记录。例如，“用户今天心情不好”可能具有临时性和敏感性；“用户喜欢每周用通俗语言总结项目”则可能在明确范围和审核规则下持续有用。

记录需要内容与向量以外的信息，至少包括记忆 ID、归属与租户，相关 Agent、任务或会话范围，分类、来源、创建时间、最后确认时间、状态、保留或过期规则，以及召回所需的权限背景。纠正应留下可识别的生命周期事件，便于解释早期事实为何曾被使用。删除请求应能从发起追踪到移除或删除标记，并覆盖适用的派生索引。

召回时，相关性只是条件之一。检索路径先确定调用者权限与用途，再在允许范围内检索，并说明选中了什么记忆、为什么选中。这样，系统才能解释实际注入行动的状态。

## 按生命周期管理记忆

长期 Agent 记忆有明确的生命周期，可以减少意外遗忘和无意积累。

1. **记录。** 接收对话事件或工具结果，同时保留产生它的身份和会话背景。
2. **分类。** 区分偏好、任务状态、决策、已验证事实、摘要，以及敏感或临时内容。
3. **接纳或拒绝。** 按持久性、敏感性、同意和预期价值筛选。部分信息只留在会话中，密钥等秘密信息留在专门的安全存储中。
4. **限定范围并标注。** 绑定获准的用户、租户、Agent、任务、会话或业务域，附带来源和时间。
5. **按需检索。** 在允许的记忆中匹配当前任务，控制噪声、延迟与跨边界暴露。
6. **纠正、替代或反馈。** 授权用户与运维人员可以修订错误、过时状态，并保留足够的事件历史解释变化。
7. **过期或删除。** 对记忆的可用表达落实保留规则和删除请求。
8. **审计与测量。** 记录写入、召回、策略结果与生命周期动作，评估收益是否足以支持成本和风险。

Oracle 的建议与此一致：持久保存需要明确选择，记忆需要来源与时间；在接入 Agent 循环前，先定义存储范围，以及接纳、更新、删除和检索规则。[相关实现建议](https://blogs.oracle.com/developers/agent-memory-is-not-rag)也适用于不同底层平台。

## Claude 公开宣布了什么，还有什么需要核实

发布说明展示产品行为，完整架构需要进一步核实。下表区分已宣布行为和生产采购仍需追问的问题。

| Anthropic 已公开宣布 | 所引发布说明尚未确立 |
| --- | --- |
| 2026 年 7 月 10 日，分类记忆条目替代每日摘要 | 跨供应商或跨模型的导出与迁移契约 |
| 记忆在云端 Chat 与 Cowork 之间使用 | 组织可独立于 Claude 产品界面运行的企业记忆结构 |
| 用户可以编辑或删除记住的 Topics | 外部生产流程所需的完整保留、删除传播、审计与来源语义 |
| 敏感主题在用户开启设置前被排除 | 适用于各组织数据分类与业务用途的通用策略引擎 |
| Team 与 Enterprise 默认关闭记忆 | 具体组织应如何按自身风险配置记忆 |

右栏并不判定这些能力在 Anthropic 其他产品或文档中不存在，只说明本篇引用的发布说明尚未提供相关依据。架构与采购决策应结合已核实文档、契约和限定范围的技术评估。

## MemTensor 与 MemOS 在其中的角色

MemTensor 为 AI 应用构建记忆基础设施，并研究长期记忆与持续学习。工作包括 Memory³ 研究、MemOS 记忆系统，以及记忆原生基座模型研究，目标是帮助应用保留有用背景、支持个性化，并持续利用信息。

MemOS 面向跨对话、跨任务的背景保留。Cloud API 支持从对话生成记忆、检索相关信息、更新和删除记录，以及通过反馈纠正记忆。这些能力帮助应用记住偏好，将相关背景带入后续交互。MemOS 同时提供托管 Cloud 与开源部署方案，公开能力见 [MemOS Cloud 概述](https://memos-docs.openmem.net/cn/memos_cloud/getting_started/overview/)和 [API 概览](https://memos-docs.openmem.net/cn/api_docs/start/overview/)。

对用户而言，良好的记忆管理意味着减少重复说明，并随着偏好与项目变化保持连续性。独立记忆层则为应用提供明确的检索、更新与删除操作，持续管理这些背景。

## 生产 Agent 的治理检查清单

启用持久记忆前，团队应当能够书面回答：

- **用途：** 每类记忆服务什么决策或流程？哪些信息排除在保留范围外？
- **范围：** 哪些用户、租户、Agent、项目、任务与会话组合可以写入和召回？
- **接纳：** 谁可以把交互转为持久记忆？适用什么审核或置信度规则？
- **来源：** 运维人员能否找到来源事件、工具结果、策略版本、时间与最后确认记录？
- **权限：** 召回是否使用与底层业务数据一致的身份和授权背景？
- **敏感性：** 密钥、受监管字段与敏感个人主题如何排除、脱敏或获得明确同意？
- **纠正：** 相关用户或授权人员能否编辑、替代或质疑记忆，并保持状态一致？
- **删除与保留：** 保留期限是什么，如何验证记录、索引、缓存与下游表达的删除？
- **可观测性：** 写入、检索与策略拒绝是否有日志，可重建 Agent 动作？
- **评估：** 是否同时衡量召回收益，以及过期、无关召回与范围泄露？

这些检查直接面向运行。用户体验可以简洁，底层处理需要精确。

## Claude 更新带来的启示

Claude 的可编辑记忆让用户更接近被记住的状态，也把记忆作为一组条目来管理。这一方向提高了 Agent 体验的基准。

AI 进入日常工作后，有用的记忆可以减少重复，并长期保留相关背景。Claude 展示了易于管理的价值，MemOS 则向其他 AI 应用提供跨交互保留与复用背景的记忆能力。实际问题始终是：应用记住什么、在哪里使用，以及用户如何让它保持准确。
