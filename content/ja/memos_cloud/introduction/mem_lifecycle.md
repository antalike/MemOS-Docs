---
title: 記憶ライフサイクル管理
desc: MemOS では、記憶は静的に保存されるのではなく、時間と使用状況に応じて絶えず進化します。
---


## 1. 機能紹介
1つの記憶は生成されてから、徐々に安定した長期的な好みとして定着することもあれば、古くなったり無効になったりしてクリーンアップされることもあります。
:::note
**ヒント**<br>
この一連の進化プロセスは **記憶ライフサイクル管理** と呼ばれ、その目的は記憶ライブラリを「クリーンで秩序ある」状態に保つことです<br>

* **最近有用な項目**はアクティブな状態を維持し、いつでも呼び出しやすくします；<br>

* **長期的に安定した事実**は定着させ、重複とノイズを減らします；<br>

* **古くなった、または競合する情報**はアーカイブまたは削除され、一貫性とコンプライアンスを保証します。<br>
:::
> 注意すべき点として、ライフサイクル管理が注目するのは**記憶項目の保存レイヤーにおける進化**です；一方で、具体的な1回の推論で「ある記憶項目を呼び出すかどうか」は、依然としてスケジューリング機構によって決定されます。

<br>

:::note{icon="ri:customer-service-2-fill"}
**ライフサイクル段階の概要**
:::

| **段階** | **説明** | **システム動作** |
| ---- | --- | --- |
| Generated<br>生成  | 新たに生成された記憶オブジェクトで、ソース、タイムスタンプ、信頼度などのメタ情報を持つ | 初期状態で保存レイヤーに格納され、後続の使用を待つ |
| Activated<br>活性化  | 推論またはタスク内で参照され、高頻度のアクティブ状態に入る | スケジューリング機構によって選択されやすくなる |
| Merged<br>統合  | 過去の記憶と意味的な重複がある、またはユーザー補足データが存在するため、システムがそれを新バージョンとして統合する | 複数の記録が圧縮・統合され、更新後の安定した項目が形成される |
| Archived<br>アーカイブ  | 長期間アクセスされておらず、自動的にコールドストレージ状態へ降格される | 特殊な検索または遡及時にのみ有効化される |
| Expired<br>期限切れ、任意  | アーカイブ後にさらにタイムアウトする、またはポリシーによって無効と判定される | インデックスからクリーンアップされ、推論には参加せず、最小限のログのみを残す |
| Frozen<br>凍結、特殊状態  | 重要またはコンプライアンス上の記憶がロックされ、変更が許可されない | 完全な履歴バージョンを保持し、監査とコンプライアンス追跡をサポートする |


## 2. 事例：オンライン教育アシスタントの記憶ライフサイクル

:::note{icon="ri:message-2-line"}
MemOS を使って **オンライン教育アシスタント** を構築し、学生の数学問題の解答を支援していると仮定します。
:::

**生成（Generated）**

*   学生が初めて使用したときにこう言います：「私はいつも二次関数と一次関数を混同してしまいます。」
    
*   システムは次の記憶を抽出します：
    

```json
{"fact": "学生は二次関数と一次関数をよく混同する", "confidence": 0.8, "timestamp": "2025-09-11"}

```

*   状態：**Generated**
    
*   動作：記憶ライブラリに保存され、後続の使用を待ちます。
    

---

**活性化（Activated）**

*   続く複数回の解答で、システムはこの記憶を頻繁に呼び出して問題解決を補助します。
    
*   状態：**Activated**
    
*   動作：スケジューリング機構によって優先的に MemoryCube へキャッシュされ、検索速度を向上させます。
    

---

**統合（Merged）**

*   さらに多くのやり取りが進むにつれ、システムは学生が一次関数と二次関数を混同するだけでなく、指数関数も混同しやすいことを発見します。
    
*   システムは複数の類似した記憶を次のように統合します：
    

```json
{"fact": "この学生は関数の知識ポイントに混同があり、特に一次、二次、および指数関数で顕著である", "confidence": 0.95}

```

*   状態：**Merged**
    
*   動作：古い項目は圧縮され、新しいバージョンが形成され、冗長性を減らします。
    

---

**アーカイブ（Archived）**

*   3か月後、学生はすでに関数関連の知識ポイントを習得しており、システムは長い間この記憶を再びスケジューリングしていません。
    
*   状態：**Archived**
    
*   動作：MemVault（コールドストレージ）に移動され、デフォルトでは推論に参加しませんが、「学習履歴の遡及」で呼び出すことができます。
    

---

**期限切れ（Expired）**

*   さらに1年が経過し、その学生は新しい学段階に進み、古い「中学関数の混同」の記憶はポリシーによって無効と判定されます。
    
*   状態：**Expired**
    
*   動作：インデックスから完全にクリーンアップされ、最小限の監査情報のみを残します：
    

```json
{"deleted_fact_id": "12345", "deleted_at": "2026-09-11"}

```
---

**凍結（Frozen，特殊状態）**

*   同時に、その学生の「期末成績評価レポート」はコンプライアンス文書に属し、変更は許可されません。
    
*   状態：**Frozen**
    
*   動作：ロックされ、更新は禁止され、完全な変更履歴のみが保持され、監査とコンプライアンスチェックに役立ちます。
    

## 3. 発展：深いカスタマイズを行いたい場合

| **拡張可能ポイント** | **説明** | **例** |
| --- | --- | --- |
| 状態遷移条件 | 各状態のトリガー条件を制御する | 「7日間未使用の場合 → アーカイブ」 |
| 統合と圧縮 | 類似記憶の処理方法を定義する | 複数の「SF映画が好き」を、より高い信頼度を持つ1つの事実に統合する |
| 競合解決 | タイムスタンプまたはソースが矛盾する記憶を処理する | 「最新で古い項目を上書き」を選ぶ、または「並列で保持」 |
| クリーンアップ機構 | 削除条件を設定し、インデックス規模を制御する | 低信頼度またはユーザーが撤回した記憶を削除する |
| 監査追跡 | 削除された項目の最小限のメタ情報を保持するかどうかを決定する | コンプライアンス要件の下で「トレーサビリティログ」を有効化する |
