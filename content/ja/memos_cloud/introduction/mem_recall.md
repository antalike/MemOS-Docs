## 1. 機能紹介

記憶リコールは、ユーザーが新しいリクエストを開始した際に、タスクに最も関連する記憶断片を迅速に検索する役割を担います。

*   **役割**：モデルが回答を生成する際に、「ゼロから開始」するのではなく、ユーザーの履歴、嗜好、コンテキストを組み合わせることを保証します。
    
*   **返却結果**：リコールされた記憶には、事実 / 嗜好 / ツール / スキル の4種類が含まれます。
    
    *   トレーサブル：各記憶にはソース、タイムスタンプ、信頼度が付随します。
        
    *   高い制御性：開発者は、どの記憶を下流ロジックに入れるかを完全に把握できます。
 
*   **特徴**：
    
    *   無意識リコール：ユーザーは以前の選択や嗜好を繰り返して説明する必要がありません
        
    *   構造化出力：記憶タイプを区別し、開発者が注入するかどうかを制御しやすくします

*   **機能サポート**：
    *   [フィルターを設定](/memos_cloud/features/basic/filters)：直近30日間の会話のみを検索；嗜好タイプの記憶のみを対象にし、事実タイプは不要、など

    *   [リコール戦略を調整](memos_cloud/mem_operations/search_memory)：類似度しきい値を上げ、信頼度 ≥0.9 の記憶のみを返す、など

    *   [ナレッジベース](/memos_cloud/features/advanced/knowledge_base)、[マルチモーダルメッセージ](/memos_cloud/features/basic/multimodal)に基づく記憶内容をリコール


## 2. 上級：深いカスタマイズを行いたい場合

MemOS では、リコールと補完の実装方式は単一の経路ではなく、複数の戦略とコンポーネントの組み合わせによって実現されます。異なるシナリオでは異なる設定が必要になる場合があり、本節では主要な工程とカスタマイズ可能なポイントを列挙し、業務ニーズに応じて柔軟に選択できるようにします。

| **階層** | **カスタマイズ可能ポイント** | **例** |
| --- | --- | --- |
| 出力ガバナンスと監査 | セーフティネット | 補完指令の前に「回答はコンプライアンス規範を遵守してください」という一文を自動で追加 |
|  | ログとトレースバック | 呼び出しのたびに使用した記憶項目と few-shot の選択を記録 |
|  | A/B テスト | 2セットの連結テンプレートを同時に実行し、ユーザー満足度の差を比較 |
