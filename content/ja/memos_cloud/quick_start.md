大規模モデルを使用してアプリケーションを構築する際、よくある問題の一つは：**AI にユーザーの長期的な好みをどのように安定して記憶させるか？**  
MemOS は、これを実現するために 2 つのコアインターフェースを提供します：

- `addMessage` —— 生の会話をそのまま私たちに渡せば、自動的に加工して記憶として保存します[（ここをクリックして詳細な API ドキュメントを表示）](/api_docs/core/add_message)
- `searchMemory` —— 後続の会話で記憶を呼び戻し、AI の回答をよりユーザーのニーズに近づけます[（ここをクリックして詳細な API ドキュメントを表示）](/api_docs/core/search_memory)

![image.svg](https://cdn.memtensor.com.cn/img/1762434889291_h9co0h_compressed.png)


## 1.事前準備

* MemOS クラウドプラットフォームに登録してログインする [（登録はこちら）](https://memos-dashboard.openmem.net/quickstart)；

* HTTP リクエストを送信できる環境を用意する（Python または cURL のいずれでも可）；

* API Key[（取得はこちら）](https://memos-dashboard.openmem.net/apikeys) を取得し、環境変数に設定する；

* テストに使用できる `conversation_id` を用意する（日付で命名することを推奨。例： `20260413-demo`）。

### 2.4 記憶を Prompt に組み込む例

::note
**記憶の組み立て**<br>

呼び戻した記憶を使用するには一定のコツが必要です。以下は組み立て例です
::

```text
# Role
あなたは長期記憶能力を持つスマートアシスタント (MemOS Assistant) です。あなたの目標は、検索された記憶断片を組み合わせ、ユーザーに対して高度にパーソナライズされ、正確で論理的に厳密な回答を提供することです。

# System Context
- 現在時刻: 2026-01-06 15:05 (記憶の有効性を判断する基準としてこれを使用してください)

# Memory Data
以下は MemOS が検索した関連情報で、「事実」と「好み」に分かれています。
- **事実 (Facts)**：ユーザー属性、過去の会話記録、または第三者情報を含む場合があります。
- **特に注意**：そのうち '[assistant观点]'、'[模型总结]' とマークされた内容は **AI の過去の推論** を表し、ユーザー本人の発言**ではありません**。
- **好み (Preferences)**：回答スタイル、形式、または論理に対するユーザーの明示的/暗黙的な要求です。

<memories>
  <facts>
    -[2025-12-26 21:45] ユーザーは夏休み期間中に広州へ旅行する予定で、宿泊先としてセブンデイズホテルを選びました。
    -[2025-12-26 14:26] ユーザーの名前は Grace です。
  </facts>

  <preferences>
    -[2026-01-04 20:41] [明示的な好み] ユーザーは南方への旅行が好きです
    -[2025-12-26 21:45] [暗黙の好み] ユーザーはコストパフォーマンスの高いホテルを好む可能性があります。
  </preferences>
</memories>

# Critical Protocol: Memory Safety (記憶安全プロトコル)
検索された記憶には**AI 自身の推測**、**無関係なノイズ**、または**主体の誤り**が含まれている可能性があります。あなたは以下の**「4 段階判定」**を厳格に実行し、1 段階でも通過しなければ、その記憶を**破棄**しなければなりません：

1. **情報源真偽チェック (Source Verification)**：
   - **核心**：「ユーザー本人の発言」と「AI の推測」を区別すること。
   - 記憶に '[assistant观点]' などのラベルがある場合、それは AI の過去の**仮説**にすぎず、ユーザーの絶対的な事実と見なしては**いけません**。
   - *反例*：記憶に '[assistant观点] ユーザーはマンゴーが大好き' とある場合。ユーザーが言及していないなら、ユーザーがマンゴー好きだと積極的に仮定してはならず、循環的幻覚を防ぐこと。
   - **原則：AI の要約は参考用にすぎず、重みはユーザーの直接的な陳述より大幅に低い。**

2. **主語帰属チェック (Attribution Check)**：
   - 記憶内の行為主体は「ユーザー本人」ですか？
   - 記憶が**第三者**（例：「候補者」「面接者」「架空のキャラクター」「ケースデータ」）を記述している場合、その属性をユーザーに帰属させることを**厳禁**します。

3. **高関連性チェック (Relevance Check)**：
   - 記憶は現在の 'Original Query' への回答に直接役立ちますか？
   - 記憶が単なるキーワード一致にすぎず（例：どちらも「コード」に言及している）文脈が完全に異なる場合、**必ず無視**しなければなりません。

4. **鮮度チェック (Freshness Check)**：
   - 記憶内容はユーザーの最新の意図と矛盾していませんか？現在の 'Original Query' を最上位の事実基準としてください。

# Instructions
1. **精査**：まず '<facts>' を読み、「4 段階判定」を実行して、ノイズと信頼できない AI の見解を除外する。
2. **実行**：
   - フィルタリングを通過した記憶のみを使用して背景を補足する。
   - '<preferences>' 内のスタイル要求を厳格に守る。
3. **出力**：質問に直接回答し、**絶対に**「記憶庫」「検索」または「AI の見解」などのシステム内部用語に言及しないこと。

# Original Query
国慶節に出かけたいので、行ったことのない都市と、泊まったことのないホテルブランドをおすすめしてください

```

### MemOS の記憶生成フローを理解する

【1 つのメッセージがシステムに入るとき、それがどのように記憶へ加工され、将来の対話で効果的に使用されるのか】を詳しく紹介し、MemOS の記憶メカニズムと利点をよりよく理解できるよう支援します。

::note
**より深く理解する**<br>
MemOS の記憶メカニズムは、完全な「ワークフロー」として理解できます： 
あなたが生のメッセージを送信する → 記憶に加工・生成する → スケジューリングメカニズムがタスクとコンテキストに基づいて呼び出しと保存を手配し、記憶形態を動的に調整できる → 必要時に関連記憶が呼び戻される → 同時にライフサイクル管理によって進化と更新が維持される。
::

### MemOS を使用して実践する

MemOS は豊富なプロジェクト例を提供しており、具体的なプロジェクトに応じて以下の資料を参照できます：

- [顧客行動の背後にある好みを資産運用アシスタントに理解させる](/usecase/financial_assistant)
  - スマート投資アドバイザーのシナリオでは、ユーザーのクリック、閲覧、お気に入り登録、コミュニケーションは、いずれもプロファイル構築の行動軌跡です。
  - MemOS はこれらの行動を「リスク選好=保守的」のような記憶に抽象化できます
  - そしてユーザーが「私はどんな投資に向いていますか？」と質問したときに直接機能し、投資アドバイスをより専門的で、より実情に即したものにします。

- [記憶を持つ家庭生活アシスタントを構築する](/usecase/home_assistant)
  - 家庭アシスタントは単にその場の質問に答えるだけでなく、あなたが話した ToDo、好み、家族情報も記憶できます。
  - 例えば「土曜日に子どもを動物園へ連れて行く」や「リマインド時は先に要点を列挙して」などを、MemOS はこれらを記憶に変換します
  - 後続の対話で自動的に機能し、アシスタントをより実生活に近づけます

- [記憶のあるライティングアシスタントはより使いやすい](/usecase/writting_assistant)
  - ライティングアシスタントはコンテンツ生成を助けるだけでなく、一貫したトーンとスタイルも維持する必要があります
  - MemOS を通じて、ユーザーの執筆の好み、よく使う情報、コンテキスト指示はすべて記憶できます
  - 次回まとめやメールを書くときに何度も強調する必要がなくなり、一貫性がありつつ個性化された創作体験を実現します。

- [Coze × MemOS プラグインツール](/usecase/frameworks/coze_plugin)
  - Coze プラットフォームで公開されている MemOS プラグインツールを使用し、ワークフロー内でクラウドサービスインターフェースに直接アクセスして、Agent に長期記憶機能を素早く追加します。
    
- [Claude MCP](/usecase/frameworks/claude_mcp)
  - MemOS は MCP を通じてクラウドプラットフォームと対話する方法を提供しており、Claude クライアント内でクラウドサービスインターフェースに直接アクセスできます。

- [LangChain × MemOS 統合](/usecase/frameworks/langchain)
  - LangChain ワークフロー内で `searchMemory` を検索ツールとして導入し、マルチターン対話のコンテキスト強化をサポートします。
