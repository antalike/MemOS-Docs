## 1. いつ記憶フィルターを使用するか

大規模な記憶を処理する際には、検索可能な記憶の範囲を正確に制御する必要があります。記憶フィルター（Filter）は、検索範囲を細かく制御する機能を提供し、主に以下を含みます：

*   **指定したエージェントで記憶をフィルタリング**：同一ユーザーの複数エージェントの記憶の中から、指定したエージェントに属する記憶を絞り込みます。
    
*   **時間に基づいて記憶をフィルタリング**：タイムスタンプによって検索範囲を限定し、特定の日または期間内の記憶を問い合わせます。
    
*   **カスタム範囲の記憶を指定**：メタ情報のカスタムフィールドに基づき、業務条件に合致する記憶のみを検索します。
    

## 2. 動作原理
1. **正確なフィルタリング**：設定したフィルター条件に基づき、ユーザーの記憶に対して強いフィルタリングを行い、制約を満たす候補記憶エントリを正確に保持します。
2. **検索リコール**：フィルタリング後の候補記憶の中で、[記憶検索](/memos_cloud/mem_operations/search_memory) を実行し、その中からユーザークエリに最も関連する記憶断片をリコールします。

## 3. フィルター構造の説明

JSON 形式を使用して記憶フィルターを定義でき、最上位層で論理演算子を使用して複数のフィルター条件を組み合わせることができます。

```json
# 基本構造は以下のとおりです
{
    "and": [  # または'or'
        { "field_name": "value" },
        { "field_name": { "operator": "value" } }
    ]
}
```

## 4. 使用可能なフィールドと演算子

### 4.1 インスタンスフィールド

フィールドの詳細な説明は（[6. その他の機能](/memos_cloud/mem_operations/add_message)）を参照してください

| フィールド名 | データ型 | 演算子 | 例 |
| --- | --- | --- | --- |
| agent\_id | str | `=` | `{"agent_id":"agent_123"}` |
| app\_id | str | `=` | `{"app_id":"app_123"}` |

### 4.2 メタ情報フィールド

記憶検索（search）時に、メッセージ追加（[add](/memos_cloud/mem_operations/add_message)）段階で info を通じて書き込まれたメタ情報属性をフィルタリングできます。より良い検索パフォーマンスを得るために、以下の 4 つの一般的なフィールドを優先的に使用することを推奨します（データベースインデックスが追加されており、クエリ速度がより高速です）。フィールドの詳細な説明は（[6. その他の機能](/memos_cloud/mem_operations/add_message)）を参照してください。

| フィールド名 | データ型 | 演算子 | 例 |
| --- | --- | --- | --- |
| business_type | str | `=` | `{"business_type":"買い物"}` |
| biz_id | str | `=` | `{"biz_id":"order_123456"}` |
| scene | str | `=` | `{"scene":"支払い"}` |
| custom_status | str | `=` | `{"custom_status":"VIP3"}` |


### 4.3 タグフィールド

| フィールド名 | データ型 | 演算子 | 例 |
| --- | --- | --- | --- |
| tags | list | `contains` | `{"tags": {"contains": "finance"}}` |

### 4.4 時間フィールド

| フィールド名 | データ型 | 演算子 | 例 |
| --- | --- | --- | --- |
| create\_time | str | `lt`, `gt`, `lte`, `gte` | `{"create_time": {"gte": "2025-12-10"}}`<br>`{"create_time": {"gt": "2025-12-10 15:00:00"}}`|
| update\_time | str | `lt`, `gt`, `lte`, `gte` | `{"update_time": {"lte": "2025-12-10"}}`<br>`{"update_time": {"lt": "2025-12-10 23:00:00"}}`| |

## 5. 使用例

::note
**ヒント**<br> ルートノードは `and` または `or` でなければならず、かつ一連の条件を組み合わせる必要があります。論理演算子のネストは許可されていません；<br>
`filter` 内で `user_id` を指定することはサポートされていません。
::

以下の記憶フィルターを使用することで、一般的なフィルタリング要件を満たすことができ、フィルターロジックを再構築する必要はありません。

---

**エージェント**

```json
# 以下のいずれかのエージェントに関連する記憶をフィルタリング
"filter" : {
    "or": [
        {"agent_id": "agent_123"},
        {"agent_id": "agent_456"}
    ]
}
```

**メタ情報**

```json
# カスタムメタ情報 info 内の属性をフィルタリング
"filter" : {
    "and": [
        {"business_type":"旅行"}, # マクロな業務カテゴリ
        {"biz_id":"travel_001"}, # 中核業務識別子
        {"scene":"支払い"}, # メッセージが発生した具体的な環境または対話段階
        {"custom_status":"v1"} # カスタム状態/マーク
    ]
}
```

**タグ**

```json
# 指定タグを含む記憶をフィルタリング
"filter" : {
    "and": [
        {"tags": {"contains": "天気"}}
    ]
}
```

**日付範囲**

```json
# 2025年12月の記憶をフィルタリング
"filter" : {
    "and": [
        {"create_time": {"gt": "2025-12-01"}},
        {"create_time": {"lt": "2026-01-01"}}
    ]
}

# 最近の一定期間に更新された記憶をフィルタリング
"filter" : {
    "and": [
        {"update_time": {"gt": "2025-12-10"}}
    ]
}
```

**多次元**

```json
# あるユーザーのQ4におけるカスタマーサービスアシスタントとの請求書に関する記憶をフィルタリング
"filter" : {
    "and": [
        {"agent_id": "customer_service"},
        {"scene":"請求書"},
        {"create_time": {"gt": "2025-10-01"}},
        {"create_time": {"lt": "2026-01-01"}}
    ]
}
```
