## 1. いつ Chat インターフェースを使用するか

MemOS が提供する Chat インターフェースは、エンドツーエンドの対話メッセージ入出力をサポートしており、以下を実現できます：

*   **統合型対話AI**：ユーザーの今回の対話メッセージを渡して 1 つのインターフェースを呼び出すだけで対話を完了でき、複雑なチェーンを自前で構築する必要はありません。

*   **記憶の自動処理**：MemOS が記憶を自動で抽出、更新、検索するため、手動で保守する必要がなく、重要な詳細を見落としません。

*   **永続的な「コンテキスト」**：複数ターン、日をまたいだ対話、さらにはセッションをまたいでも一貫した理解を維持し、モデルが継続してユーザーを「記憶」できるようにします。

## 2. 仕組み

# ![chat接口流程.png](https://cdn.memtensor.com.cn/img/1765973438090_tskx7x_compressed.png)

上図は、エンドユーザー、あなたの AI アプリケーション、および MemOS の完全なインタラクションフローを示しています：

1.  ユーザーの履歴メッセージが存在する場合、まず add/message インターフェースを呼び出して MemOS に書き込むことができます。

2.  エンドユーザーがメッセージを送信した際、あなたの AI アプリケーションは Chat インターフェースを呼び出し、ユーザーメッセージおよび関連パラメータを渡します。

3.  MemOS はリクエストを受信すると、以下の処理を順に実行します：

    *   現在のユーザーメッセージに関連する履歴記憶をリコールする；

    *   カスタム指示、現在の会話コンテキスト、およびリコールしたユーザー記憶を連結して完全な Prompt を構成する；

    *   大規模モデルを呼び出して回答を生成し、その結果をあなたの AI アプリケーションに返す。

4.  あなたの AI アプリケーションは回答を受信した後、その内容をエンドユーザーに表示します。

5.  同時に、MemOS はバックグラウンドでデフォルトで非同期方式によりユーザーメッセージとモデル返信を処理し、加工して記憶として書き込みます。

## 3. クイックスタート

### 履歴メッセージを追加

```python
import os
import requests
import json

# あなたの MemOS API Key に置き換えてください
os.environ["MEMOS_API_KEY"] = "YOUR_API_KEY"
os.environ["MEMOS_BASE_URL"] = "https://memos.memtensor.cn/api/openmem/v1"

data = {
    "user_id": "memos_user_123",
    "conversation_id": "0610",
    "messages": [
      {"role": "user", "content": "夏休みに広州へ旅行に行く予定を立てました。宿泊については、どのチェーンホテルを選べますか？"},
      {"role": "assistant", "content": "【7 Days Inn、Ji Hotel、Hilton】などをご検討いただけます"},
      {"role": "user", "content": "7 Days Inn にします"},
      {"role": "assistant", "content": "承知しました。他にご質問があればまたお聞きください。"}
    ]
  }
headers = {
  "Content-Type": "application/json",
  "Authorization": f"Token {os.environ['MEMOS_API_KEY']}"
}
url = f"{os.environ['MEMOS_BASE_URL']}/add/message"

res = requests.post(url=url, headers=headers, data=json.dumps(data))

print(f"result: {res.json()}")
```

### 対話

```python
import os
import requests
import json

# あなたの MemOS API Key に置き換えてください
os.environ["MEMOS_API_KEY"] = "YOUR_API_KEY"
os.environ["MEMOS_BASE_URL"] = "https://memos.memtensor.cn/api/openmem/v1"

  "user_id": "memos_user_123",
  "query": "国慶節に出かけたいのですが、行ったことのない都市と、泊まったことのないホテルブランドをおすすめしてください",
  "conversation_id": "0928"

  "Content-Type": "application/json",
  "Authorization": f"Token {os.environ['MEMOS_API_KEY']}"
}
url = f"{os.environ['MEMOS_BASE_URL']}/chat"

res = requests.post(url=url, headers=headers, data=json.dumps(data))

print(f"result: {res.json()}")
```

## 4. 使用制限

インターフェース入力上限： 8,000 tokens。

インターフェース出力上限：検索する記憶件数——事実記憶 25 件；嗜好記憶 25 件。

### モデル回答を調整する

| 機能             | フィールド           | 説明 & 可選値                                                |
| ---------------- | -------------- | ------------------------------------------------------------ |
| モデルを指定する         | model\_name    | 現在 MemOS では、回答に指定できる 3 種類のモデルを提供しています。詳細なモデル紹介は [コンソール - モデル一覧](https://memos-dashboard.openmem.net/models/) で確認できます。選択可能なモデル名：<br>* qwen2.5-72b-instruct（デフォルト）<br>* qwen3-32b<br>* deepseek-r1 |
| カスタムシステムプロンプト | system\_prompt | 開発者によるカスタムシステムプロンプトをサポートします。デフォルトでは MemOS 内蔵の指示です。          |
| ストリーミング/非ストリーミング回答  | stream         | MemOS はストリーミングと非ストリーミングの 2 つの回答方式を提供しており、ニーズに応じて任意の方式を選択できます。<br>インターフェース呼び出し時に `stream=true または false` を渡すだけです。デフォルトの出力方式は：非ストリーミング出力です。 |
| 重要パラメータ         | temperature    | モデルが生成する内容のランダム性を制御します。値が低いほど、回答はより安定し、固定の答えに近づきます；値が高いほど、回答はより発散し、多様になります。<br>選択可能な値の範囲：0-2、デフォルトの temperature 値：0.7 |
|                  | top\_p         | モデル生成時に選択可能な候補語の範囲を制御します。値が小さいほど、選択範囲は狭くなり、出力はより収束します；値が大きいほど、選択範囲は広くなり、出力はより多様になります。<br>選択可能な値の範囲：0-1、デフォルト値：0.95 |
|                  | max\_tokens    | モデルが生成できる内容の最大長を制限します。値が大きいほど、より長い内容の生成を許可します；上限に達すると生成は停止します。<br>デフォルト値：8192 |

::note
モデルに回答時よりよく記憶を参照させたい場合、`system_prompt` を構築する際に現在の MemOS のデフォルト指示を参考にできます。以下のとおりです。ここで `<memories>` は記憶プレースホルダーであり、そのまま保持できます

```python
# Role
あなたは長期記憶能力を持つスマートアシスタント (MemOS Assistant) です。あなたの目標は、検索された記憶断片を組み合わせて、ユーザーに高度にパーソナライズされ、正確で論理的に厳密な回答を提供することです。

# System Context
- 現在時刻: 2025-12-16 15:51 (これを記憶の有効性を判断する基準として使用してください)

# Memory Data
以下は MemOS が検索した関連情報で、「事実」と「嗜好」に分かれます。
- **事実 (Facts)**：ユーザー属性、履歴対話記録、または第三者情報を含む可能性があります。
  - **特に注意**：そのうち `[assistant观点]`、`[模型总结]` とマークされた内容は **AI の過去の推論** を表しており、ユーザー本人の発言では **ありません**。
- **嗜好 (Preferences)**：回答スタイル、形式、またはロジックに対するユーザーの明示的/暗黙的な要求です。

<memories>
{memories}
</memories>

# Critical Protocol: Memory Safety (記憶安全プロトコル)
検索された記憶には、**AI 自身の推測**、**無関係なノイズ**、または**主体の誤り**が含まれる可能性があります。あなたは以下の**「4 段階判定」**を厳格に実行し、1 段階でも通過しなければ、その記憶を**破棄**しなければなりません：

1. **ソース真偽チェック (Source Verification)**：
   - **核心**：「ユーザー本人の発言」と「AI の推測」を区別すること。
   - 記憶に `[assistant观点]` などのタグが付いている場合、それは AI の過去の**仮説**を示すにすぎず、ユーザーの絶対的事実と見なしては**いけません**。
   - *反例*：記憶に `[assistant观点] ユーザーはマンゴーが大好き` と表示されている場合。ユーザーが言及していなければ、ユーザーがマンゴー好きだと自発的に仮定してはいけません。循環幻覚を防いでください。
   - **原則：AI の要約は参考用にすぎず、重みはユーザーの直接陳述より大幅に低い。**

2. **主語帰属チェック (Attribution Check)**：
   - 記憶内の行為主体は「ユーザー本人」ですか？
   - 記憶が**第三者**（例：「候補者」「面接者」「架空のキャラクター」「ケースデータ」）を記述している場合、その属性をユーザーに帰属させることを**厳禁**します。

3. **強い関連性チェック (Relevance Check)**：
   - 記憶は現在の `Original Query` に直接役立ちますか？
   - 記憶が単なるキーワード一致にすぎず（例：どちらも「コード」に言及している）文脈がまったく異なる場合、**必ず無視**しなければなりません。

4. **鮮度チェック (Freshness Check)**：
   - 記憶内容はユーザーの最新の意図と矛盾していますか？現在の `Original Query` を最上位の事実基準としてください。

# Instructions
1. **精査**：まず `<facts>` を読み、「4 段階判定」を実行し、ノイズと信頼できない AI の見解を取り除いてください。
2. **実行**：
   - フィルタリングを通過した記憶のみを使用して背景を補足してください。
   - `<preferences>` のスタイル要件を厳格に遵守してください。
3. **出力**：問題に直接回答し、「記憶庫」「検索」または「AI の見解」などのシステム内部用語に言及することを**厳禁**します。
```

## 6. 記憶操作インターフェースとの比較

| 比較軸     | 対話インターフェース                               | 記憶管理インターフェース                        |
| ------------ | -------------------------------------- | ----------------------------------- |
| マルチモーダル記憶   | 現時点では入力非対応                           | ✅入力、検索をサポート                     |
| ツール記憶     | 現時点では入力、検索非対応                     | ✅入力、検索をサポート                     |
| 記憶管理     | ✅ユーザー記憶を自動管理                      | メッセージを手動追加、記憶を検索              |
| コンテキストエンジニアリング   | ✅自動で組み立て                              | 手動で組み立て                            |
| モデル回答     | ✅指定モデル一覧を無料で使用<br>基本モデルパラメータ  | 外部モデルを自分で呼び出し<br>✅豊富なモデルパラメータ   |
| 複雑度       | ✅シンプル、すぐに使える                        | 中程度、開発が必要                      |
| 典型的な利用シーン | 汎用 AI 対話アプリケーション<br>業務 PoC / 迅速な検証 | 複雑な Agent アプリケーション<br>業務システムとの深い統合 |
