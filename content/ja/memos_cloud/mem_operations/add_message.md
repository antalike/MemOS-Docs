## 1. メッセージを追加するには？

記憶の基礎は元のメッセージ内容に由来します。MemOS は、追加したメッセージを一律に記憶として加工し、後続の検索と利用に使用します。AI アプリケーションを構築する際、すでに MemOS を使用してユーザー記憶管理を開始しているかどうかにかかわらず、実際のシナリオに応じて適切な追加タイミングを選択できます。例えば以下があります：

*   **一括インポート**：既存のユーザー過去対話をワンクリックで MemOS にインポートし、初期記憶をすばやく構築します；
    
*   **リアルタイム追加**：ユーザーがメッセージを送信するたびに、リアルタイムでメッセージを MemOS に追加します；
    
*   **ターン単位で追加**：業務要件に応じて、数ターンごとにユーザーメッセージを MemOS に追加するよう設定します。
    
::note
**&nbsp;なぜ記憶が重要なのですか？**
<div style="padding-left: 2em;">

* セッションをまたぐ長期記憶を実現でき、対話終了後の情報喪失を防げます；

* インタラクションの蓄積に伴い、AI がますます「**ユーザーを理解**」できるようになります；

* セッション中に継続的に新しい情報を書き込み、ユーザー記憶を動的に更新します；

* 複数のアプリや製品間で同一ユーザーの記憶を共有し、一貫したユーザー体験を実現します。
</div>
::


## 2. 主要パラメータ

*   **ユーザー識別子（user\_id）**：メッセージが属する一意のユーザーを識別するために使用します。現在、追加されるすべての対話情報は、具体的かつ一意のユーザー識別子に関連付ける必要があります。
    
*   **セッション識別子（conversation\_id）**：メッセージが属する一意のセッションを識別するために使用します。現在、追加されるすべての対話情報は、具体的かつ一意のセッション識別子に関連付ける必要があります。
    
*   **メッセージ（messages）**：MemOS に追加するユーザーと AI の対話内容の順序付きメッセージリストです。
    

## 3. 動作原理

*   **情報抽出**：MemOS はシステム内部で LLM を使用して、メッセージ内の事実、好みなどを抽出し、記憶として処理します。これには、事実記憶、嗜好記憶、ツール記憶などが含まれます。
    
*   **競合解決**：既存の記憶に重複または矛盾があるかをチェックし、更新を完了します。
    
*   **記憶保存**：最終的に生成された記憶は、ベクトルデータベースとグラフデータベースを使用して保存され、後続の検索時に高速にリコールできるようにします。
    

以上のすべての処理フローは、`add/message`インターフェースを呼び出すだけでトリガーでき、ユーザー記憶を手動で操作する必要はありません。


## 4. クイックスタート

```python
import os
import requests
import json

# あなたの MemOS API Key に置き換えてください
os.environ["MEMOS_API_KEY"] = "YOUR_API_KEY"
os.environ["MEMOS_BASE_URL"] = "https://memos.memtensor.cn/api/openmem/v1"

data = {
    "user_id": "memos_user_123",
    "conversation_id": "0610",
    "messages": [
      {"role": "user", "content": "夏休みに広州へ旅行に行く予定です。宿泊ならどのチェーンホテルが選べますか？"},
      {"role": "assistant", "content": "【7 Days Inn、Ji Hotel、Hilton】などをご検討いただけます"},
      {"role": "user", "content": "7 Days Inn を選びます"},
      {"role": "assistant", "content": "承知しました。他にご質問があればまた聞いてください。"}
    ]
  }
headers = {
  "Content-Type": "application/json",
  "Authorization": f"Token {os.environ['MEMOS_API_KEY']}"
}
url = f"{os.environ['MEMOS_BASE_URL']}/add/message"

res = requests.post(url=url, headers=headers, data=json.dumps(data))

print(f"result: {res.json()}")
```
:::note
どの記憶が生成されたか知りたいですか？上記のコードをワンクリックでコピーして実行し、[**記憶を検索**](/memos_cloud/mem_operations/search_memory)へ進んでください。
:::

## 5. その他の使用方法

### 対話をリアルタイムでインポート

ユーザーがモデルの返信を受け取るたびに、リアルタイムでインターフェースを呼び出してメッセージを追加し、ユーザーとアシスタントの対話をいつでも MemOS と同期できます。MemOS はバックエンドで新しい対話に基づいて継続的にユーザー記憶を更新します。

```python
import os
import json
import requests


os.environ["MEMOS_API_KEY"] = "YOUR_API_KEY"
os.environ["MEMOS_BASE_URL"] = "https://memos.memtensor.cn/api/openmem/v1"

# headers と base URL
headers = {
  "Authorization": f"Token {os.environ['MEMOS_API_KEY']}",
  "Content-Type": "application/json"
}
BASE_URL = os.environ['MEMOS_BASE_URL']

def add_message(user_id, conversation_id, messages):
    data = {
        "user_id": user_id,
        "conversation_id": conversation_id,
        "messages": messages
    }
    
    res = requests.post(f"{BASE_URL}/add/message", headers=headers, data=json.dumps(data))
    result = res.json()
  
    if result.get('code') == 0: 
      print(f"✅ 追加成功")
    else:
      print(f"❌ 追加失敗, {result.get('message')}")

# ユーザーとアシスタントの対話メッセージを追加
add_message("memos_user_123", "memos_conversation_123",
            [{"role": "user", "content": "今朝5キロ走ったら、膝が少しだるいです"}, 
             {"role": "assistant", "content": "今日は5キロ走って膝が少しだるいとのことなので、関節と筋肉がまだ強度に適応している段階だと考えられます。明日は距離を3キロ前後に抑え、十分なウォームアップとクールダウンを重視することをおすすめします。これにより、トレーニングのリズムを維持しつつ、膝に回復の時間を与えられます。"}])

```

<br>

### 過去対話をインポート

すでに AI 対話アプリケーションを構築している場合、MemOS は既存のチャット履歴の一括インポートもサポートしており、対話アシスタントがユーザーを記憶し、よりパーソナライズされた返信を行えるよう支援します。

```python
# 過去対話データの例
"messages": [
  # ユーザー1日目とAIの対話
    {"role": "user", "content": "辛い食べ物が好きです", "chat_time": "2025-09-12 08:00:00"},
    {"role": "assistant", "content": "わかりました、覚えておきます。あなたは辛い味の食べ物が好きなのですね。", "chat_time": "2025-09-12 08:01:00"},
  # 数日後のユーザーとAIの対話
    {"role": "user", "content": "でも油が多すぎるものはあまり好きじゃないです。例えば麻辣火鍋や毛血旺みたいなものです", "chat_time": "2025-09-25 12:00:00"},
    {"role": "assistant", "content": "あなたはさっぱりしていて辛みのある料理をより好むのですね。あなたに合った辛いグルメをいくつかおすすめできますよ~", "chat_time": "2025-09-25 12:01:00"}
]
```

<br>

### 記憶フィルターと組み合わせてメッセージを追加
MemOS は、開発者が自身の要件に応じて、選択した記憶範囲から記憶をリコールすることをサポートしています。メッセージ追加時に以下のフィールドを使用して生成された記憶にマークを付けることで、記憶検索時に[記憶フィルター（filter）](/memos_cloud/features/basic/filters)を使用して正確なフィルタリングを行えます。


1. **同一ユーザーが複数の Agent と（複数のアプリ内で）チャットする**

メッセージ追加時に `agent_id` `app_id` などの情報を付与して、現在のユーザー対話に関連する Agent、アプリを識別し、「同一ユーザーの異なる Agent / App 配下の記憶」を区別します。

```python
data = {
  "user_id": "memos_user_123",
  "agent_id":"health_assistant", #開発者が渡す現在の対話の agent。
  "conversation_id": 0610,
  "messages":[
    {"role": "user", "content": "今朝5キロ走ったら、膝が少しだるいです"}, 
    {"role": "assistant", "content": "今日は5キロ走って膝が少しだるいとのことなので、関節と筋肉がまだ強度に適応している段階だと考えられます。明日は距離を3キロ前後に抑え、十分なウォームアップとクールダウンを重視することをおすすめします。"
    }
  ]
}

# 後続の検索では、"agent_id":"health_assistant" を渡して、ユーザーとこのアシスタントのチャット記憶を検索できます。
```

<br>

2. **既存のタグ体系を使って、記憶を意味分類する**

MemOS は各記憶に対して自動的にタグを生成しますが、これらのタグはあなたの業務で使用しているタグと完全には一致しない可能性があります。メッセージ追加時にカスタムの`tags`を付与すると、MemOS はあなたが提供したタグの意味に基づいて、記憶内容に関連タグを自動適用します。

```python
data = {
  "user_id": "memos_user_123",
  "conversation_id": 0610,
  "tags":["運動アドバイス","フィットネス計画","運動記録"], #開発者が渡す「フィットネスアシスタント話題分類」用のカスタムタグ。
  "messages":[
    {"role": "user", "content": "今朝5キロ走ったら、膝が少しだるいです"}, 
    {"role": "assistant", "content": "今日は5キロ走って膝が少しだるいとのことなので、関節と筋肉がまだ強度に適応している段階だと考えられます。明日は距離を3キロ前後に抑え、十分なウォームアップとクールダウンを重視することをおすすめします。"
    }
  ]
}

# 後続の検索では、"tags":"運動アドバイス" を渡して、「運動アドバイス」を中心としたユーザー記憶を検索できます。
```

::note
さらに詳しく知りたい場合は、[カスタムタグ](/memos_cloud/features/basic/custom_tags)を参照してください
::

<br>

3. **既存の業務情報を使って、正確にフィルタリングする**

メッセージ追加時に`info`を付与し、より多くの構造化された業務フィールドやカスタム補足情報、たとえば`scene = 注文`などを渡すことで、業務の次元に応じて現在のシナリオ、業務ライン、ソース、状態などを正確に区別するために使用します。


```python
data = {
  "user_id": "memos_user_123",
  "conversation_id": 0610,
  "messages":[
    {"role": "user", "content": "都合の良い時間の航空券を探してください"}, 
    {"role": "assistant", "content": "ご都合の良い時間の便をいくつか見つけました：\n1. 北京 → 上海、2月15日 08:30出発、12:30到着\n2. 北京 → 上海、2月15日 14:00出発、18:00到着\n3. 北京 → 上海、2月16日 09:00出発、13:00到着\nどの便を予約するか、あるいは他の条件で絞り込む必要があるか教えてください。"
    }
  ],
  "info":{
    "scene":"航空券"
  }
}

# 後続の検索では、"info":{"scene":"航空券"} を渡して、「航空券購入」業務シナリオを中心としたユーザー記憶を検索できます。
```

<br>

**使用上のヒント**

`info`は任意のカスタムキーと値のペアを渡すことをサポートしており、すべてのフィールドは正常に保存および検索できます。

現在のシステムは、以下のフィールドに対してより優れたクエリ性能サポートを提供しています（これらのフィールドにはすでにインデックスが追加されているためです）：
- business_type（業務タイプ）
- biz_id（業務一意識別子）
- scene（業務または対話シナリオ）
- custom_status（カスタム状態）

上記フィールドの使用は必須ではありません。他のカスタムフィールドを使用しても機能上は完全に同一ですが、検索性能に差が出る可能性があります。

::note
`info`はフラット化されたキーと値のペア構造であり、フィールド名とフィールド値はどちらも文字列型である必要があり、検索時の条件フィルタリングに使用されます。文字列以外の値は、渡す前に文字列へ変換する必要があります。
::

## 6. その他の機能

| **機能** | **フィールド** | **説明** |
| --- | --- | --- |
| マルチモーダルメッセージ | `messages` | 追加に使用する対話メッセージリスト。<br>サポートされるロールタイプには以下が含まれます：user / assistant / system / tool；<br>サポートされるメッセージタイプには以下が含まれます：<br>• テキスト<br>• ドキュメント、画像。詳細は[マルチモーダルメッセージ](/memos_cloud/features/basic/multimodal)を参照してください。<br>• ツール呼び出し情報。詳細は[ツール呼び出し](/memos_cloud/features/advanced/tool_calling)を参照してください。 |
| 非同期モード | `async_mode` | メッセージ追加後の処理方式を制御し、非同期と同期の2つのモードをサポートします。詳細は[非同期モード](/memos_cloud/features/basic/async_mode)を参照してください。 |
| パブリック記憶への書き込み | `allow_public` | 現在のユーザー対話メッセージから生成された記憶を、プロジェクトレベルのパブリック記憶へ書き込むかどうかを制御します。プロジェクト内のすべてのユーザーで共有され、デフォルトでは無効です。 |
| ナレッジベース記憶への書き込み | `allow_knowledgebase_ids` | 現在のユーザー対話メッセージから生成された記憶を、指定したプロジェクト関連ナレッジベースへ書き込むかどうかを制御します。該当ナレッジベースにアクセス可能なすべてのユーザーで共有されます。デフォルトは空で、使用時には書き込み先のナレッジベース一覧を渡せます。詳細は[ナレッジベース](/memos_cloud/features/advanced/knowledge_base)を参照してください。 |
