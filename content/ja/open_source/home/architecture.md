## コアモジュール

### MOS (Memory Operating System、記憶オペレーティングシステム)

MemOS のオーケストレーション層——複数の記憶タイプ（プレーンテキスト、活性化、パラメータ化）にまたがる予測的・非同期スケジューリングを管理し、**マルチユーザー・マルチセッション**の記憶ワークフローをオーケストレーションします。

**コア機能**
 - **統一 API ゲートウェイ**：すべての記憶操作（追加、検索、更新、転送、ロールバック）に対して一貫したインターフェースを提供
 - **ワークフローオーケストレーション**：MemCube、MemReader、MemScheduler などのコンポーネントの実行フローを調整
 - **相互運用性サポート**：記憶交換プロトコル (MIP) を通じてモデル間・デバイス間の記憶移行を実現
 - **リソーススケジューリング**：計算リソースをインテリジェントに割り当て、リアルタイム応答とバックグラウンド処理の需要をバランス


### MemCube (記憶コンテナ)

MemCube は MemOS の**モジュール化記憶ストレージユニット**であり、独立かつポータブルな「メモリカード」と見なすことができます。各 MemCube は特定のユーザー、エージェント、またはセッション専用にサービスを提供でき、1 種類または複数種類の記憶タイプを格納します。

**マルチ Cube サポート (Multi-Cube):**

MemOS は**複合ビュー (Composite View)** を通じて複数の MemCube を同時に操作することをサポートし、柔軟な記憶の分離と共有を実現します：

| 操作タイプ | 戦略 | 適用シナリオ |
|---------|------|---------|
| **書き込み** | ファンアウト書き込み (Fan-out Write) | 記憶をユーザー個人 Cube とプロジェクト共有 Cube に同時に書き込む |
| **読み取り** | 並列検索 (Parallel Search) | 複数の Cube を同時に照会し、結果を集約してグローバルビューを提供 |

**動的管理機能:**

 - **ホットプラグ対応**：実行時に MemCube を動的に登録、更新、または削除可能
 - **コンテナ化ストレージ**：セッション、モデル、デバイス間での記憶の安全な転送をサポート
 - **分離保証**：異なるユーザーまたはアプリケーション間の記憶データが相互に分離されることを保証

### 非同期追加メカニズム (Asynchronous Addition)

高並行シナリオにおいて低レイテンシを維持するために、MemOS は **MemScheduler** を利用してバックグラウンドスケジューリングを行う非同期記憶追加モード (`async_mode`) を提供します：

| 記憶タイプ | 処理戦略 | 利点 |
|---------|---------|------|
| **テキスト記憶** | 高速抽出 + 非同期処理 | API は即座に基本結果を返し、複雑な処理はバックグラウンドで実行 |
| **嗜好記憶** | 完全非同期処理 | API 応答レイテンシを最大限削減 |

**MemScheduler の役割：**
非同期タスクスケジューラとして、以下を担当します：
 - バックグラウンド処理タスクの優先度キューを管理
 - 再インデックス化、グラフ推論などの計算集約型操作を調整
 - タスク状態を監視し、処理の一貫性を確保

### 記憶タイプ体系

MemOS はさまざまなニーズを満たすために、いくつかの専用記憶タイプをサポートしています：

#### 1. パラメータ化記憶(**近日公開**)

 - **特性**：知識がモデル重みに固定化され、推論はゼロレイテンシ
 - **適用シナリオ**：安定したドメイン知識、コアスキル
 - **ライフサイクル**：長期持続、高い更新コスト

#### 2. 活性化記憶

 - **特性**：実行時 KV Cache と隠れ状態、高速再利用
 - **適用シナリオ**：マルチターン対話コンテキスト、頻繁にアクセスされる背景情報
 - **ライフサイクル**：短期有効、セッションレベルで維持

#### 3. プレーンテキスト記憶

構造化または非構造化の知識ブロック；編集可能で、追跡可能であり、高速更新、パーソナライズ、およびマルチエージェント共有に適しています。

| 記憶サブクラス | ストレージ構造 | コア利点 | 典型的な用途 |
|---------|---------|---------|---------|
| **GeneralTextMemory** | ベクトルストレージ | セマンティック検索が柔軟で、メタデータフィルタリングをサポート | 非構造化ドキュメント、チャット履歴 |
| **TreeTextMemory** | グラフ構造ストレージ | 階層化された構成で、マルチホップ推論をサポート | 構造化知識ベース、ユーザープロファイル |


::note{title="アーキテクチャ選定の推奨"}
**開始の推奨**<br>：`GeneralTextMemory` から始めて概念を迅速に検証
**進化パス**<br>：業務の複雑性の向上に伴い、`TreeTextMemory` を段階的に導入して構造化知識を処理
::

#### 基盤サポートコンポーネント

MemOS の基盤モジュールは標準化された機能を提供し、システムの拡張性と一貫性を確保します：

| コンポーネントカテゴリ | コア機能 | 実装例 |
|---------|---------|---------|
| **テキスト処理** | インテリジェント分割、記憶抽出 | Chunkers, MemReaders |
| **ベクトル化** | テキスト埋め込み生成 | Embedders (bge-m3, text-embedding-3-large) |
| **ストレージインターフェース** | 複数データベース適応 | GraphDBs (Neo4j, Qdrant, PolarDB) |
| **モデル接続** | 統一 LLM インターフェース | LLMs (OpenAI, Ollama) |
| **品質最適化** | 検索結果再ランキング | Rerankers (bge-reranker-v2-m3) |

## コード構成アーキテクチャ

MemOS プロジェクトは明確に構成されており、プラグアンドプレイをサポートします：

```
src/memos/
    api/           # API 定義
    chunkers/      # テキスト分割ツール
    configs/       # 設定スキーマ
    context/       # ログコンテキスト
    embedders/     # 埋め込みモデル
    graph_dbs/     # グラフデータベースバックエンド (例: Neo4j)
    vec_dbs/       # ベクトルデータベースバックエンド (例: Qdrant)
    llms/          # LLM コネクタ
    mem_agent/     # ディープ検索
    mem_chat/      # 記憶拡張チャットロジック
    mem_cube/      # MemCube 管理
    mem_feedback   # 記憶フィードバック
    mem_os/        # MOS オーケストレーション
    mem_reader/    # 記憶リーダー
    mem_scheduler/ # 記憶スケジューリングモジュール
    memories/      # 記憶タイプ実装
    multi_mem_cube/# マルチビュー cube
    parsers/       # 解析ツール
    reranker/      # 再ランキングモジュール
    templates/     # プロンプトテンプレート
    types/         # 型定義
```

::note{title="開発ガイド"}
**プロのヒント**<br>
 - **迅速な実験**：`examples/` ディレクトリ内のサンプルを使用して機能を迅速に検証
 - **高度なカスタマイズ**：`src/` 内のモジュール実装を参照して二次開発を実施
 - **設定管理**：すべてのコンポーネントは `configs/` を通じた柔軟な設定をサポート
::

## 拡張性

MemOS は**モジュール化設計**です。
独自の記憶タイプ、ストレージバックエンド、または LLM コネクタを追加するには、最小限の変更だけで済みます——これは**統一設定とファクトリパターン**によるものです。

::note
**プロのヒント**<br>
[貢献](/open_source/contribution/overview) 新しいバックエンドを追加するか、独自の記憶タイプを共有してください——簡単にプラグインできます。
::
