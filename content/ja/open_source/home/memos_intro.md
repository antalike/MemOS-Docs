LLMs の発展に伴い、それらは複雑なタスク――たとえば複数ターン対話、長期計画、意思決定、そして個別化されたユーザー体験――を処理する必要があり、**構造化され、管理され、進化するメモリを扱う能力をそれらに与えること**は、真に長期的な知能と適応性を実現するうえで極めて重要になっています。

しかし、ほとんどの主流の LLMs は依然として静的なパラメータ化メモリ（モデル重み）に大きく依存しています。そのため、知識の更新、メモリ使用の追跡、または進化するユーザー嗜好の蓄積が困難になります。結果は何でしょうか？知識の更新コストが高く、挙動が脆弱で、個別化が限定的です。

**MemOS** は、メモリを統一構造、ライフサイクル管理、およびスケジューリングロジックを備えた**中核的なモジュール化システムリソース**として再定義することで、これらの課題を解決します。これは、あなたの LLM と外部知識ソースの間に位置する Python ベースのレイヤーを提供し、**永続的で、構造化され、高効率なメモリ操作**を実現します。

MemOS を使用すると、あなたの LLM は時間とともに知識を保持し、より堅牢にコンテキストを管理し、説明可能で監査可能なメモリを用いて推論できるようになり――よりスマートで、信頼性が高く、適応的な AI の振る舞いを解き放ちます。


::note
**ヒント**<br>  MemOS は、静的なパラメータ化重みと動的でユーザー固有のメモリとの間のギャップを埋めるのに役立ちます。
  これを、平文メモリと活性化メモリのプラグアンドプレイモジュールを備えた、あなたのエージェントの「脳」と考えてください。
::

## なぜ MemOS が必要なのか？

LLMs は強力ですが、パラメータ化メモリ（重み）に大きく依存しており、これらの重みは検査、更新、または共有が困難です。
典型的なベクトル検索 (RAG) は外部の事実の検索には役立ちますが、統一されたガバナンス、ライフサイクル制御、またはエージェント間共有を欠いています。

**MemOS** はこれを変えます。
これをメモリのオペレーティングシステムと考えてください：
オペレーティングシステムが CPU、RAM、ファイルをスケジュールするように、MemOS は複数のメモリタイプ――パラメータ化重みから一時キャッシュ、さらに平文で追跡可能な知識まで――を**スケジュール、変換、および統治**します。

::note
**より深い理解**<br>  MemOS は、パラメータ化、活性化、および平文メモリをライフサイクル全体にわたって融合することで、あなたの LLM の進化を支援します。
::


## コア構成ブロック
### MemCubes

**柔軟なコンテナ**であり、1 種類または複数種類のメモリタイプを収容します。
各ユーザー、セッション、またはエージェントは、それぞれ独自の MemCube を持つことができます――交換可能で、再利用可能で、追跡可能です。

### メモリライフサイクル

各メモリユニットは、次の状態を流れることができます：

- **生成** → **活性化** → **統合** → **アーカイブ** → **凍結**

各ステップは、**来歴追跡**と監査ログによってバージョン管理されます。古いメモリは、復元または反事実シミュレーションのために「タイムマシン」で以前のバージョンに戻すことができます。


### 操作とガバナンス

モジュールには以下が含まれます：

- **MemScheduler** — 最適な再利用のためにメモリタイプを動的に変換します。
- **MemLifecycle** — 状態遷移、統合、およびアーカイブを管理します。
- **MemGovernance** — アクセス制御、編集、コンプライアンス、および監査追跡を処理します。


::note
**コンプライアンスの注意**<br>    各メモリユニットは完全な来歴メタデータを保持しているため、誰がそれを作成、変更、または照会したかを監査できます。
::


## マルチビュー・メモリ

MemOS はライフサイクル全体にわたって**3 種類のメモリ形式**を融合します：

| タイプ           | 説明                                          | ユースケース                                       |
|----------------| ---------------------------------------------------- | ---------------------------------------------- |
| **パラメータメモリ** | 知識がモデル重みに蒸留されている               | 常設スキル、安定したドメイン事実          |
| **活性化メモリ** | 推論での再利用のための KV Cache と隠れ状態      | 高速な複数ターンチャット、低遅延生成   |
| **平文メモリ**  | テキスト、文書、グラフ、ベクトルチャンク、ユーザー可視の事実| セマンティック検索、進化、説明可能なメモリ  |

時間の経過とともに：

- 頻繁に使用される平文メモリは、パラメータ化重みに蒸留できます。
- 安定したコンテキストは、高速注入のために KV Cache に昇格されます。
- 使用頻度が低い、または古くなった知識は降格できます。


## MemOS の違いは何か？

- ハイブリッド検索 — シンボリック検索とセマンティック検索のハイブリッド、ベクトル検索とグラフ検索のハイブリッド。
- マルチエージェントおよびマルチユーザーグラフ — プライベートおよび共有。
- 来歴と監査追跡 — 各メモリユニットは統治され、説明可能です。
- 安定したコンテキストを再利用するための自動 KV Cache 昇格。
- メモリのライフサイクルスケジューリング — 古い事実や肥大化した重みの呼び出しを削減します。


## 誰に適しているか？

- **複数ターンで進化するメモリ**を必要とする対話エージェント
- **コンプライアンス、ドメイン更新、および個別化**を扱うエンタープライズ Copilot
- **共有知識グラフ**上で協調するマルチエージェントシステム
- ブラックボックスのプロンプトではなく、モジュール化され、検査可能なメモリを望む AI ビルダー

## 重要なポイント

**MemOS** は、あなたの LLM を「単に tokens を予測するだけ」から、
**記憶**し、**推論**し、**適応**できる知的進化システムへと
アップグレードします――まるであなたのエージェント思考のオペレーティングシステムのように。

**MemOS を使えば、あなたの AI は単に事実を保存するだけでなく――成長します。**

## 主な機能

- **モジュール型メモリアーキテクチャ**: 平文、活性化 (KV Cache)、およびパラメータ化 (adapters/LoRA) メモリをサポートします。
- **MemCube**: すべてのメモリタイプのための統一コンテナであり、シンプルな読み込み/保存と API アクセスを備えています。
- **MOS**: LLMs 向けのメモリ強化システムであり、プラグアンドプレイのメモリモジュールを備えています。
- **グラフベースのバックエンド**: 構造化され、説明可能なメモリのために、Neo4j およびその他のグラフデータベースをネイティブにサポートします。
- **統合が容易**: HuggingFace、Ollama、およびカスタム LLMs と併用できます。
- **拡張可能**: 独自のメモリモジュールまたはバックエンドを追加できます。
