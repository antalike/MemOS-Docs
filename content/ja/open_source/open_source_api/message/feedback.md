---
title: フィードバックの追加
desc: ユーザーによる大規模モデルの応答へのフィードバック内容を送信し、MemOS が不正確な記憶をリアルタイムで修正、最適化、または削除できるようにします。
---


**インターフェースパス**：`POST /product/feedback`
**機能説明**：このインターフェースは、ユーザーによる AI 応答または記憶内容へのフィードバックを処理するために使用されます。`feedback_content` を分析することで、システムは **MemCube** に保存されている誤った事実を自動的に特定して修正するか、ユーザーの正負のフィードバックに基づいて記憶の重みを調整できます。

## 1. コアメカニズム：記憶修正ループ

**FeedbackHandler** は、通常の追加インターフェースよりも、より精緻な制御ロジックを提供します：

* **正確な修正 (Precise Correction)**：`retrieved_memory_ids` を提供することで、システムは特定のいくつかの検索結果を直接修正でき、他の記憶への誤修正を回避します。
* **コンテキスト分析**：`history`（対話履歴）を組み合わせることで、システムはフィードバックの背後にある真の意図を理解できます（例：「あなたの言い方は間違っています。今の私の会社は B ではなく A です」）。
* **結果の返却**：`corrected_answer=true` を有効にすると、インターフェースは記憶修正の処理完了後、新しい事実に基づいて生成された修正後の回答を返そうとします。

## 2. 主要インターフェースパラメータ
このインターフェースのコアパラメータ定義は以下のとおりです：

| パラメータ名 | 型 | 必須 | デフォルト値 | 説明 |
| :--- | :--- | :--- | :--- | :--- |
| **`user_id`** | `str` | はい | - | ユーザー一意識別子。 |
| **`history`** | `list` | はい | - | 直近の対話履歴。フィードバックのコンテキストを提供するために使用されます。 |
| **`feedback_content`** | `str` | はい | - | **コア：** ユーザーのフィードバックテキスト内容。 |
| **`writable_cube_ids`**| `list` | いいえ | - | 記憶修正を実行する対象 Cube のリスト。 |
| `retrieved_memory_ids` | `list` | いいえ | - | オプション。前回検索された、修正が必要な特定の記憶 ID リスト。 |
| `async_mode` | `str` | いいえ | `async` | 処理モード：`async` (バックグラウンド処理) または `sync` (リアルタイム処理して待機)。 |
| `corrected_answer` | `bool` | いいえ | `false` | システムが記憶修正後に修正済みの新しい回答を返す必要があるかどうか。 |
| `info` | `dict` | いいえ | - | 追加メタデータ。 |

## 3. 動作原理

1. **競合検出**：`FeedbackHandler` はフィードバックを受け取った後、`history` と `writable_cube_ids` 内の既存の記憶事実を比較します。
2. **特定と更新**：
    * `retrieved_memory_ids` が提供されている場合、対応するノードを直接更新します。
    * ID が提供されていない場合、システムはセマンティックマッチングによって最も関連性の高い古い記憶を見つけて上書きするか、無効としてマークします。
3. **重み調整**：態度が曖昧なフィードバックに対して、システムは特定の記憶項目の `confidence`（信頼度）または信頼性レベルを調整します。
4. **非同期実行**：`async` モードでは、修正ロジックは `MemScheduler` によって非同期に実行され、インターフェースは直ちに `task_id` を返します。

## 4. クイックスタート例


```python
from memos.api.client import MemOSClient

client = MemOSClient(api_key="...", base_url="...")

# シナリオ：ユーザーの職業に関する AI の誤った記憶を修正
res = client.add_feedback(
    user_id="dev_user_01",
    feedback_content="もうダイエットしていないので、今は食事制限をする必要はありません。",
    history=[
        {"role": "assistant", "content": "あなたはダイエット中ですが、最近は摂取する食べ物のカロリーをコントロールしていますか？"},
        {"role": "user", "content": "もうダイエットしていないので..."}
    ],
    writable_cube_ids=["private_cube_01"],
    # 正確な修正を実現するため、具体的な誤った記憶 ID を指定
    retrieved_memory_ids=["mem_id_old_job_123"],
    corrected_answer=True # AI に新しい事実に基づいて再度私に返信するよう要求
)

if res and res.code == 200:
    print(f"修正進捗: {res.message}")
    if res.data:
        print(f"修正後の返信: {res.data}")
```


## 5. 使用シナリオ
### 5.1 AI の誤った推論を修正
手動介入：管理バックエンドに「修正」ボタンを提供し、管理者が AI によって抽出された記憶項目の誤りを発見した場合、このインターフェースを呼び出して手動で修正します。
### 5.2 古くなったユーザーの嗜好を更新
ユーザーによる即時修正：対話 UI において、ユーザーが「覚え違いです」「そうではありません」などの発話をした場合、このインターフェースを自動的にトリガーし、is_feedback=True を利用して記憶のリアルタイム浄化を実現できます。

::note
フィードバックが公共知識ベースに関わる場合、現在のユーザーがその Cube に対する書き込み権限を持っていることを確認してください。
::
