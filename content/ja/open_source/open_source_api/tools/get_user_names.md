---
title: ユーザーの逆引き検索 (Get User Names)
desc: 記憶の一意識別子 (ID) を通じて、この記憶が属するユーザー名を逆引き検索します。
---

**インターフェースパス**：`POST /product/get_user_names_by_memory_ids`
**機能説明**：このインターフェースは「逆方向トレース」機能を提供します。システムログまたは共有ストレージで特定の `memory_id` を取得したものの、その生成者を特定できない場合、このインターフェースを使用して対応するユーザー名を一括取得できます。

## 1. コアメカニズム：メタデータのトレーサビリティ

MemOS のストレージアーキテクチャでは、生成された各記憶エントリは元のユーザーのメタデータにバインドされています。このインターフェースは以下のロジックによりトレースを実行します：

* **多対一マッピング**：一度に複数の `memory_id` の入力をサポートし、システムは対応するユーザーリストを返します。
* **管理の透明性**：このツールは通常、管理バックエンドで使用され、管理者が共有 Cube 内の異なるエントリの貢献者を識別するのに役立ちます。



## 2. 主要インターフェースパラメータ

リクエストボディの定義は以下のとおりです：

| パラメータ名 | 型 | 必須 | 説明 |
| :--- | :--- | :--- | :--- |
| **`memory_ids`** | `list[str]` | はい | 問い合わせ対象の記憶一意識別子のリスト。 |

## 3. 動作原理 (MemoryHandler)

1. **ID 解析**：**MemoryHandler** は ID リストを受信した後、グローバルインデックステーブルを照会します。
2. **関係検索**：システムは下層の永続化レイヤー（または関係グラフノード）から、関連する `user_id` または `user_name` 属性を抽出します。
3. **データマスキング**：システム設定に基づき、対応するユーザー表示名または識別子を返します。

## 4. クイックスタート例

SDK を使用して逆引き検索を実行します：

```python
from memos.api.client import MemOSClient

client = MemOSClient(api_key="...", base_url="...")

# 照会対象の記憶 ID リストを準備
target_ids = [
    "2f40be8f-736c-4a5f-aada-9489037769e0",
    "5e92be1a-826d-4f6e-97ce-98b699eebb98"
]

# クエリを実行
res = client.get_user_names_by_memory_ids(memory_ids=target_ids)

if res and res.code == 200:
    # res.data は通常、マッピング辞書またはユーザーリストを返す
    print(f"この記憶断片は次のユーザーに属します: {res.data}")
```
