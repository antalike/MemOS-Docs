## 1. API 紹介

MemOS オープンソースプロジェクトは、**FastAPI** で記述された高性能な REST API サービス一式を提供します。システムは **Component (コンポーネント) + Handler (ハンドラー)** アーキテクチャを採用しており、すべてのコアロジック（記憶抽出、セマンティック検索、非同期スケジューリングなど）は、標準の REST インターフェースを通じて呼び出すことができます。

### コア機能の特徴

* **多次元記憶生成**：`AddHandler` による会話、テキスト、またはドキュメントの処理をサポートし、自動的に構造化記憶へ変換します。
* **MemCube 物理分離**：Cube ID に基づき、異なるユーザーまたは知識ベース間のデータ物理分離と独立インデックスを実現します。
* **エンドツーエンドの対話クローズドループ**：`ChatHandler` により「検索 -> 生成 -> 非同期保存」の全プロセスをオーケストレーションします。
* **非同期タスクスケジューリング**：組み込みの `MemScheduler` スケジューリングエンジンにより、大規模記憶生成タスクのピークシフトと状態追跡をサポートします。
* **自己補正メカニズム**：フィードバックインターフェースを提供し、自然言語を用いて保存済みの記憶を修正またはマークすることを可能にします。

## 2. 入門ガイド

以下の 2 つのコアステップにより、記憶機能をお使いの AI アプリケーションに迅速に統合できます：

* [**記憶を追加**](./core/add_memory.md)：`POST /product/add` インターフェースを通じて、元のメッセージストリームを指定した MemCube に書き込み、生成チェーンを開始します。
* [**記憶を検索**](./core/search_memory.md)：`POST /product/search` インターフェースを通じて、セマンティック類似度に基づき複数の Cube から関連コンテキストをリコールします。

## 3. API 分類

MemOS の機能インターフェースは、以下のいくつかのカテゴリに分かれます：

* **[コア記憶 (Core)](./core/add_memory.md)**：記憶の追加、削除、変更、検索などの原子的操作を含みます。
* **[インテリジェント対話 (Chat)](./chat/chat.md)**：記憶強化付きのストリーミングまたは完全な対話応答を実現します。
* **[メッセージ管理 (Message)](./message/feedback.md)**：ユーザーフィードバック、猜你想问（Suggestion）などの拡張インタラクションインターフェースを含みます。
* **[非同期スケジューリング (Scheduler)](./scheduler/get_status.md)**：バックグラウンドの記憶抽出タスクの進捗とキュー状態を監視するために使用されます。
* **[システムツール (Tools)](./tools/check_cube.md)**：Cube 存在性検証および記憶帰属の逆引き照会などの補助機能を提供します。

## 4. 認証とコンテキスト

### 認証メカニズム
オープンソース環境では、すべての API リクエストは Header に `Authorization` フィールドを含める必要があります。
* **開発環境**：ローカルの `.env` または `configuration.md` で `API_KEY` をカスタマイズできます。
* **本番デプロイ**：`RequestContextMiddleware` を通じて OAuth2 またはより高度な本人確認ロジックを拡張することを推奨します。

### リクエストコンテキスト
* **user_id**：リクエストボディにはこの識別子を必ず含める必要があり、Handler 層での ID 追跡に使用されます。
* **MemCube ID**：オープンソース版のコア分離ユニットです。`readable_cube_ids` または `writable_cube_ids` を指定することで、データ読み書きの物理境界を正確に制御できます。
