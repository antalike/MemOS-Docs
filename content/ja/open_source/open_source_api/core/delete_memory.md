---
title: 記憶の削除 (Delete Memory)
desc: 指定された MemCube から記憶エントリ、関連ファイル、または特定のフィルタ条件に一致する記憶集合を永続的に削除します。
---

**インターフェースパス**：`POST /product/delete_memory`
**機能説明**：このインターフェースは、記憶庫の正確性とコンプライアンスを維持するために使用されます。ユーザーが特定情報の忘却を要求した場合、データが古くなった場合、または特定のアップロードファイルをクリーンアップする必要がある場合、このインターフェースを通じてベクトルデータベースとグラフデータベースで同期して物理削除を実行できます。

## 1. コアメカニズム：Cube レベルの物理クリーンアップ

オープンソース版では、削除操作は厳格な **MemCube** 分離ロジックに従います：

* **スコープ制限**：`writable_cube_ids` パラメータを通じて、削除操作は指定された記憶体内に厳格に限定され、他の Cube の内容を誤って削除することは決してありません。
* **多次元削除**：**記憶 ID**（正確）、**ファイル ID**（関連削除）、および **Filter フィルタ**（条件ロジック）の3つの次元での同時クリーンアップをサポートします。
* **原子性同期**：削除操作は **MemoryHandler** によってトリガーされ、基盤となるベクトルインデックスとグラフデータベース内のエンティティノードが同期して削除されることを保証し、「幻覚」のリコールを防ぎます。



## 2. 主要インターフェースパラメータ
コアパラメータの定義は以下のとおりです：

| パラメータ名 | 型 | 必須 | 説明 |
| :--- | :--- | :--- | :--- |
| **`writable_cube_ids`** | `list[str]` | はい | 削除操作を実行する対象 Cube のリストを指定します。 |
| **`memory_ids`** | `list[str]` | いいえ | 削除対象の記憶一意識別子のリスト。 |
| **`file_ids`** | `list[str]` | いいえ | 削除対象の元ファイル識別子のリスト。このファイルによって生成されたすべての記憶も同期してクリーンアップされます。 |
| **`filter`** | `object` | いいえ | 論理フィルタ。タグ、メタ情報、またはタイムスタンプに基づいて、条件に一致する記憶を一括削除することをサポートします。 |

## 3. 動作原理 (MemoryHandler)

1. **権限とルーティング**：システムは `user_id` によって操作権限を検証し、リクエストを **MemoryHandler** にルーティングします。
2. **ストレージの特定**：`writable_cube_ids` に基づいて、基盤の **naive_mem_cube** コンポーネントを特定します。
3. **クリーンアップタスクの分配**：
    * **ID によるクリーンアップ**：UUID に基づいてメインデータベースとベクトルデータベースで直接レコード抹消を実行します。
    * **Filter によるクリーンアップ**：まず条件に一致する記憶 ID の集合を検索し、その後一括物理削除を実行します。
4. **状態フィードバック**：操作完了後、成功状態を返し、関連内容は直ちに [**検索インターフェース**](./search_memory.md) のリコール範囲から消えます。

## 4. クイックスタート例

`MemOSClient` を使用して異なる次元の削除操作を実行します：

```python
# クライアントを初期化
client = MemOSClient(api_key="...", base_url="...")

# シナリオ1：既知の誤った単一記憶を正確に削除
client.delete_memory(
    writable_cube_ids=["user_01_private"],
    memory_ids=["2f40be8f-736c-4a5f-aada-9489037769e0"]
)

# シナリオ2：特定タグ配下のすべての古い記憶を一括クリーンアップ
client.delete_memory(
    writable_cube_ids=["kb_finance_2026"],
    filter={"tags": {"contains": "deprecated_policy"}}
)
```
## 5. 注意事項

不可逆性：削除操作は物理削除です。一度正常に実行されると、その記憶はもはや検索インターフェースを通じてリコールできません。

ファイル関連性：`file_ids` による削除時、システムは自動的にソースをたどって、そのファイルから解析された事実記憶と要約をクリーンアップします。
