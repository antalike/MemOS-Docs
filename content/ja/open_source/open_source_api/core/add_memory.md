---
title: 記憶を追加 (Add Memory)
desc: MemOS のコア本番インターフェース。MemCube の分離メカニズムを通じて、個人記憶、ナレッジベースおよびマルチテナントシナリオにおける非同期記憶生成を実現します。
---

**インターフェースパス**：`POST /product/add`
**機能説明**：これはシステムが非構造化データを保存するためのコアエントリです。対話リスト、プレーンテキストまたはメタデータを通じて、生データを構造化された記憶断片に変換することをサポートします。オープンソース版では、システムは **MemCube** を通じて記憶の物理分離と動的編成を実現します。

## 1. コアメカニズム：MemCube と分離

オープンソースアーキテクチャでは、MemCube を理解することがインターフェースを効率的に使用する鍵です：

* **分離ユニット**：MemCube は記憶生成の原子単位であり、Cube 間は完全に独立しています。システムは単一の Cube 内部でのみ重複排除と競合解決を行います。
* **柔軟なマッピング**：
    * **個人モード**：`user_id` を `writable_cube_ids` として渡すことで、個人のプライベート記憶を作成します。
    * **ナレッジベースモード**：ナレッジベースの一意識別子（QID）を `writable_cube_ids` として渡すことで、内容はそのナレッジベースに保存されます。
* **マルチターゲット書き込み**：インターフェースは複数の Cube への同時記憶書き込みをサポートし、ドメイン横断同期を実現します。


## 2. 主要インターフェースパラメータ

コアパラメータの定義は以下のとおりです：

| パラメータ名 | 型 | 必須 | デフォルト値 | 説明 |
| :--- | :--- | :--- | :--- | :--- |
| **`user_id`** | `str` | はい | - | ユーザー一意識別子。権限検証に使用されます。 |
| **`messages`** | `list/str`| はい | - | 保存対象のメッセージリストまたはプレーンテキスト内容。 |
| **`writable_cube_ids`** | `list[str]`| はい | - | **コアパラメータ**：書き込み先のターゲット Cube ID リストを指定します。 |
| **`async_mode`** | `str` | いいえ | `async` | 処理モード：`async` (バックグラウンドキュー処理) または `sync` (現在のリクエストをブロック)。 |
| **`is_feedback`** | `bool` | いいえ | `false` | `true` の場合、システムは自動的にフィードバックハンドラへルーティングし、記憶修正を実行します。 |
| `session_id` | `str` | いいえ | `default` | セッション識別子。対話コンテキストの追跡に使用されます。 |
| `custom_tags` | `list[str]`| いいえ | - | カスタムタグ。後続検索時のフィルタ条件として使用できます。 |
| `info` | `dict` | いいえ | - | 拡張メタデータ。その中のすべてのキー値ペアは後続のフィルタ検索をサポートします。 |
| `mode` | `str` | いいえ | - | `async_mode='sync'` の場合にのみ有効で、`fast` (高速) または `fine` (精細) を選択できます。 |

## 3. 動作原理 (Component & Handler)

リクエストがバックエンドに到達すると、システムは **AddHandler** によってコアコンポーネントをスケジューリングし、以下のロジックを実行します：

1. **マルチモーダル解析**：`MemReader` コンポーネントが `messages` を内部記憶オブジェクトに変換します。
2. **フィードバックルーティング**：`is_feedback=True` の場合、Handler は対話末尾をフィードバックとして抽出し、既存記憶を直接修正し、新しい事実は生成しません。
3. **非同期分配**：`async` モードの場合、`MemScheduler` はタスクをタスクキューに投入し、インターフェースは即座に `task_id` を返します。
4. **内部編成**：アルゴリズムはターゲット Cube 内で編成ロジックを実行し、重複排除と融合を通じて記憶品質を最適化します。

## 4. クイックスタート例

標準化された呼び出しには `MemOSClient` SDK の使用を推奨します：

```python
from memos.api.client import MemOSClient

# クライアントを初期化
client = MemOSClient(api_key="...", base_url="...")

# シナリオ1：個人ユーザーに記憶を追加
client.add_message(
    user_id="sde_dev_01",
    writable_cube_ids=["user_01_private"], 
    messages=[{"role": "user", "content": "私は R 言語の ggplot2 を学習しています。"}],
    async_mode="async",
    custom_tags=["Programming", "R"]
)
# シナリオ2：ナレッジベースに内容をインポートし、フィードバックを有効化
client.add_message(
    user_id="admin_01",
    writable_cube_ids=["kb_finance_2026"],
    messages="2026年の財務監査プロセスが更新されました。添付を参照してください。",
    is_feedback=True, # フィードバックとしてマークして旧版プロセスを修正
    info={"source": "Internal_Portal"}
)
```
