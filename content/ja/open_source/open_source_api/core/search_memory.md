title: 検索メモリ (Search Memory)
desc: MemCube 分離メカニズムに基づき、セマンティック検索と論理フィルタリングを利用して、メモリライブラリから最も関連性の高いコンテキスト情報を再呼び出しします。
---

**インターフェースパス**：`POST /product/search`
**機能説明**：本インターフェースは MemOS が検索拡張生成 (RAG) を実現する中核です。これは複数の分離された **MemCube** をまたいでセマンティックマッチングを行い、関連する事実、ユーザー設定、およびツール呼び出し記録を自動的に再呼び出しできます。

## 1. コアメカニズム：Readable Cubes

クラウドサービスの単一ユーザービューとは異なり、オープンソース版インターフェースは **`readable_cube_ids`** によって非常に柔軟な検索範囲制御を実現しています：

* **Cube 横断検索**：複数の Cube ID を同時に指定できます（例：`[ユーザー私有Cube, 企業共通知識ベースCube]`）。アルゴリズムは、これらの分離されたメモリから最も関連性の高い内容を並列に再呼び出しします。
* **ソフトシグナル重み**：`session_id` を渡すことで、システムは再呼び出し時にそのセッション内の内容を優先的に考慮します。これは関連性を高めるための「重み」としてのみ機能し、強制フィルタではありません。
* **絶対分離**：`readable_cube_ids` リストに含まれていない Cube の内容は、アルゴリズムレベルで完全に不可視であり、マルチテナント環境におけるデータ安全性を保証します。



## 2. 主要インターフェースパラメータ

コア検索パラメータの定義は以下のとおりです：

### 検索基礎
| パラメータ名 | 型 | 必須 | 説明 |
| :--- | :--- | :--- | :--- |
| **`query`** | `str` | はい | ユーザーの検索クエリ文であり、システムはこれに基づいてセマンティックマッチングを行います。 |
| **`user_id`** | `str` | はい | リクエスト送信者の一意識別子であり、認可とコンテキスト追跡に使用されます。 |
| **`readable_cube_ids`**| `list[str]`| はい | **コアパラメータ**：今回の検索で読み取り可能な Cube ID リストを指定します。 |
| **`mode`** | `str` | いいえ | **検索戦略**：`fast` (高速), `fine` (精細), `mixture` (混合) から選択可能です。 |

### 再呼び出し制御
| パラメータ名 | 型 | デフォルト値 | 説明 |
| :--- | :--- | :--- | :--- |
| **`top_k`** | `int` | `10` | 再呼び出しするテキストメモリの数量上限。 |
| **`include_preference`**| `bool` | `true` | 関連するユーザー設定メモリ（明示的/暗黙的設定）を再呼び出しするかどうか。 |
| **`search_tool_memory`**| `bool` | `true` | 関連するツール呼び出し記録を再呼び出しするかどうか。 |
| **`filter`** | `dict` | - | 論理フィルタであり、タグまたはメタデータによる正確なフィルタリングをサポートします。 |
| **`dedup`** | `str` | - | 重複排除戦略：`no` (重複排除しない), `sim` (セマンティック重複排除), `None` (デフォルトの正確なテキスト重複排除)。 |

## 3. 動作原理 (SearchHandler 戦略)

リクエストがバックエンドに到達すると、**SearchHandler** は指定された `mode` に基づいて異なるコンポーネントを呼び出し、検索を実行します：

1. **クエリ書き換え**：LLM を利用してユーザーの `query` をセマンティック強化し、マッチング精度を向上させます。
2. **マルチモードマッチング**：
    * **Fast モード**：ベクトルインデックスによって高速再呼び出しを行い、応答速度に対する要求が非常に高いシナリオに適しています。
    * **Fine モード**：再ランキング（Rerank）段階を追加し、再呼び出し内容の関連度を高めます。
    * **Mixture モード**：セマンティック検索とグラフ検索を組み合わせ、より深い関連メモリを再呼び出しします。
3. **多次元集約**：システムは事実、設定（`pref_top_k`）、およびツールメモリ（`tool_mem_top_k`）を並列検索し、結果を集約して返します。
4. **後処理重複排除**：`dedup` 設定に基づき、高度に類似したメモリエントリを圧縮します。

## 4. クイックスタート例

SDK によるマルチ Cube 結合検索：

```python
from memos.api.client import MemOSClient

client = MemOSClient(api_key="...", base_url="...")

# シナリオ：ユーザーメモリと 2 つの専門知識ベースを同時に検索
res = client.search_memory(
    user_id="sde_dev_01",
    query="以前の私の設定に基づいて、R 言語の可視化案をいくつか推薦してください",
    # 読み取り可能な Cube リストを渡す。個人空間と 2 つの知識ベースを含む
    readable_cube_ids=["user_01_private", "kb_r_lang", "kb_data_viz"],
    mode="fine",             # より正確な推薦を得るために精細モードを使用
    include_preference=True,  # 「ユーザーは簡潔なスタイルを好む」などの設定を再呼び出し
    top_k=5
)

if res:
    # 結果は memory_detail_list に含まれます
    print(f"再呼び出し結果: {res.data}")
```

## 5.上級：フィルタの使用 (Filter)
SearchHandler は複雑なフィルタをサポートしており、より細粒度な業務要件を満たします：
```python

# 例：タグが "Programming" で、かつ 2026 年以降に作成されたメモリのみを検索
search_filter = {
    "and": [
        {"tags": {"contains": "Programming"}},
        {"created_at": {"gt": "2026-01-01"}}
    ]
}

res = client.search_memory(
    query="データクレンジングロジック",
    user_id="sde_dev_01",
    readable_cube_ids=["user_01_private"],
    filter=search_filter
)
```
