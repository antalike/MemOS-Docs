---
title: メモリ詳細の取得 (Get Memory Detail)
desc: メモリの一意識別子 (ID) を通じて単一メモリの完全なメタデータを取得します。これには信頼度、背景情報、および使用記録が含まれます。
---

**インターフェースパス**：`GET /product/get_memory/{memory_id}`
**機能説明**：このインターフェースにより、開発者は単一メモリのすべての基盤的な詳細を取得できます。要約情報を返す検索インターフェースとは異なり、このインターフェースはそのメモリのライフサイクルデータ（ベクトル同期状態、AI 抽出背景など）を公開し、システム管理と障害調査の中核ツールです。

## 1. なぜ詳細を取得する必要があるのか？

* **メタデータの可視化**：AI がこのメモリを抽出した際の `confidence` と `background` を確認します。
* **ライフサイクル検証**：このメモリの `vector_sync`（ベクトル同期）が成功したか、およびその `updated_at` タイムスタンプを確認します。
* **使用追跡**：`usage` 記録を通じて、このメモリがどの会話で再呼び出しされ、生成を補助したかを追跡します。


## 2. 主要インターフェースパラメータ

このインターフェースは標準的な RESTful パスパラメータ形式を採用しています：

| パラメータ名 | 位置 | 型 | 必須 | 説明 |
| :--- | :--- | :--- | :--- | :--- |
| **`memory_id`** | Path | `str` | はい | メモリの一意識別子（UUID）。この ID は [**メモリ一覧の取得**](./get_memory_list.md) または [**検索**](./search_memory.md) の結果から取得できます。 |

## 3. 動作原理 (MemoryHandler)

1. **直接クエリ**：**MemoryHandler** によりビジネスオーケストレーション層を直接バイパスし、基盤コアコンポーネント **naive_mem_cube** と対話します。
2. **データ補完**：システムは永続化データベースから完全な `metadata` 辞書を取得して返し、いかなる意味的切り捨ても行いません。

## 4. レスポンスデータ詳細

レスポンスボディ内の `data` オブジェクトには、以下の中核フィールドが含まれます：

| フィールド名 | 説明 |
| :--- | :--- |
| **`id`** | メモリの一意識別子。 |
| **`memory`** | メモリのテキスト内容で、通常は注記（例: `[userの見解]`）を含みます。 |
| **`metadata.confidence`** | AI がこのメモリを抽出した信頼度スコア（0.0 - 1.0）。 |
| **`metadata.type`** | メモリ分類。`fact` (事実) または `preference` (好み) など。 |
| **`metadata.background`** | AI がこのメモリを抽出した理由およびそのコンテキスト背景を詳細に説明します。 |
| **`metadata.usage`** | リスト形式で、このメモリがモデルに使用された履歴時間と環境を記録します。 |
| **`metadata.vector_sync`**| ベクトルデータベース同期状態。通常は `success` です。 |

## 5. クイックスタート例

SDK を使用して詳細クエリを開始します：

```python
# 既知のメモリ ID があると仮定
mem_id = "2f40be8f-736c-4a5f-aada-9489037769e0"

# 完全な詳細を取得
res = client.get_memory_by_id(memory_id=mem_id)

if res and res.code == 200:
    metadata = res.data.get('metadata', {})
    print(f"メモリ背景: {metadata.get('background')}")
    print(f"同期状態: {metadata.get('vector_sync')}")
```
