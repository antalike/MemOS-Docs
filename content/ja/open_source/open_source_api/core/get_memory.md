desc: 指定した Cube 内の記憶コレクションをページネーション照会または全量エクスポートし、タイプによるフィルタリングおよびサブグラフ抽出をサポートします。

**インターフェースパス**：
* **ページネーション照会**：`POST /product/get_memory`
* **全量エクスポート**：`POST /product/get_all`

**機能説明**：指定した **MemCube** 内の記憶アセットを一覧表示またはエクスポートするために使用します。これら2つのインターフェースを通じて、システムが生成した元の記憶断片、ユーザー設定、またはツール使用記録を取得でき、ページネーション表示と構造化エクスポートをサポートします。

## 1. コアメカニズム：ページネーション vs. 全量エクスポート

オープンソース版では、システムは **MemoryHandler** を通じて2つの異なるコレクションアクセスモードを提供しています：

* **業務ページネーションモード (`/get_memory`)**：
    * **設計意図**：フロントエンド UI リスト向けに設計されています。`page` と `page_size` パラメータをサポートします。
    * **特性**：デフォルトで設定記憶（`include_preference`）を含み、軽量なデータロードをサポートします。
* **全量エクスポートモード (`/get_all`)**：
    * **設計意図**：データ移行または複雑な関係分析向けに設計されています。
    * **コア能力**：`search_query` を渡して関連する**サブグラフ（Subgraph）**を抽出すること、または `memory_type`（テキスト/アクション/パラメータ）に従って全量データをエクスポートすることをサポートします。


## 2. 主要インターフェースパラメータ

### 2.1 ページネーション照会パラメータ (`/get_memory`)

| パラメータ名 | 型 | 必須 | 説明 |
| :--- | :--- | :--- | :--- |
| **`mem_cube_id`** | `str` | はい | 対象 MemCube ID。 |
| **`user_id`** | `str` | いいえ | ユーザー一意識別子。 |
| **`page`** | `int` | いいえ | ページ番号（1 から開始）。`None` に設定した場合は全量エクスポートを試みます。 |
| **`page_size`** | `int` | いいえ | 1ページあたりの項目数。 |
| `include_preference` | `bool` | いいえ | 設定記憶を含めるかどうか。 |

### 2.2 全量/サブグラフエクスポートパラメータ (`/get_all`)

| パラメータ名 | 型 | 必須 | 説明 |
| :--- | :--- | :--- | :--- |
| **`user_id`** | `str` | はい | ユーザー ID。 |
| **`memory_type`** | `str` | はい | 記憶タイプ：`text_mem`, `act_mem`, `para_mem`。 |
| `mem_cube_ids` | `list` | いいえ | エクスポート対象の Cube ID リスト。 |
| `search_query` | `str` | いいえ | 指定した場合、これに基づいて検索して関連する記憶サブグラフを返します。 |

## 3. クイックスタート例

### 3.1 フロントエンドのページネーション表示 (SDK 呼び出し)

```python
# 1ページ目を取得、1ページあたり 10 件の記憶
res = client.get_memory(
    user_id="sde_dev_01",
    mem_cube_id="cube_research_01",
    page=1,
    page_size=10
)

for mem in res.data:
    print(f"[{mem['type']}] {mem['memory_value']}")
```
### 3.2 特定の事実記憶サブグラフをエクスポート
```python
# 「R 言語」に関連するすべての事実記憶を抽出
res = client.get_all(
    user_id="sde_dev_01",
    memory_type="text_mem",
    search_query="R language visualization"
)
```

## 4. レスポンス構造の説明
インターフェースは標準の業務レスポンスを返し、そのうち data には記憶オブジェクト配列が含まれます。各記憶には通常、以下のコアフィールドが含まれます：

`id`: 記憶の一意識別子であり、詳細取得 または 削除 操作の実行に使用されます。

`memory_value`: アルゴリズムによって加工された記憶テキスト。

`tags`: 関連付けられたカスタムタグ。

::note
開発者向けヒント： 記憶 ID が既知であり、その完全なメタデータ（confidence や usage 記録など）を確認したい場合は、`記憶詳細を取得`（Get_ memory_by_id）インターフェースを使用してください。 :::
