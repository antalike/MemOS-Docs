## 1. 概要

**MemFeedback** は MemOS の「やり直し薬」です。

長期記憶システムにおいて、最も頭が痛いのは多くの場合「覚えられない」ことではなく、「覚え間違えたのに直せない」ことです。ユーザーが「いいえ、私の誕生日は明日です」や「このプロジェクトのコードネームを X に変えて」と言ったとき、単純な RAG システムでは通常どうすることもできません。

MemFeedback はこれらの自然言語指示を理解し、自動的にデータベース内で衝突する記憶を正確に特定し、原子的な修正操作（たとえば古い記憶をアーカイブし、新しい記憶を書き込む）を実行できます。これにより、あなたの Agent は人間のようにやり取りの中で継続的に誤りを修正し、学習できるようになります。

---

## 2. コア機能

以下の 4 つの一般的なフィードバックシナリオを処理できます：

### 訂正 (Correction)
ユーザーが事実の誤りを指摘します。システムは乱暴に古いデータを削除するのではなく、それを**アーカイブ (Archive)** し、新しいデータを書き込みます。これにより誤りを修正するだけでなく、バージョン履歴（Traceability）も保持されます。進行中の対話（WorkingMemory）の場合は、その場で直接更新してコンテキストの一貫性を保証します。

### 追加 (Addition)
ユーザーが単に新しい情報を補足し、それが古い記憶と衝突しない場合は簡単です——そのまま新しいノードとして記憶庫に保存します。

### グローバル置換 (Keyword Replacement)
IDE における「グローバルリファクタリング」に似ています。たとえばユーザーが「すべてのドキュメント内の『張三』を『李四』に変えて」と言った場合、システムは Reranker と組み合わせて影響を受けるドキュメント範囲を自動的に特定し、関連するすべての記憶を一括更新します。

### 嗜好の進化 (Preference Evolution)
「私はパクチーを食べない」「私は Python が好き」といった嗜好を専門に処理します。システムはこの嗜好が生じた場面を記録し、ユーザープロファイルを継続的に豊かにして、Agent を使えば使うほど手になじむようにします。

## 3. コード構造

コアロジックはすべて `memos/src/memos/mem_feedback/` 配下にあります。

*   **`simple_feedback.py`**: **これを直接見ることを推奨します**。これは公式にラップされたバージョンで、LLM、ベクトルデータベース、リトリーバーがすべて組み立て済みで、すぐに使えます。
*   **`feedback.py`**: コア実装クラス `MemFeedback`。面倒で大変な作業はすべてここにあります：意図認識、衝突比較、安全リスク制御。
*   **`base.py`**: インターフェース定義。
*   **`utils.py`**: ツールボックス。

---

## 4. 主要インターフェース

メインの入口は 1 つだけです：`process_feedback()`。通常は RAG フロー終了後、ユーザーがフィードバックを返したあとに非同期で呼び出します。

### 4.1 入力パラメータ

| パラメータ | 説明 |
| :--- | :--- |
| `user_id` / `user_name` | ユーザー識別子と Cube ID。 |
| `chat_history` | 対話履歴。これにより LLM は直前に何を話していたかを把握できます。 |
| `feedback_content` | ユーザーが言ったそのフィードバック文（たとえば「違います、5時です」）。 |
| **`retrieved_memory_ids`** | **必須項目（強く推奨）**。前回の RAG 検索で取得した記憶 ID を渡します。これはシステムに「標的」を与えるのと同じで、どの記憶を修正すべきかを伝えます。渡さない場合、システムは大量の記憶から自分で再検索しなければならず、遅いだけでなく、誤って修正しやすくなります。 |
| `corrected_answer` | 修正後の返答を 1 文あわせて生成するかどうか。 |

### 4.2 出力結果

辞書を返し、今回の操作で何が変更されたかを知らせます：
*   **`record`**: データベース変更の詳細（たとえば `{ "add": [...], "update": [...] }`）。
*   **`answer`**: ユーザーへの自然言語の返答。

---

## 5. ワークフロー

MemFeedback のワークフローは、厳密な編集部のようなものです：

1.  **査読 (意図認識)**: まずユーザーが訂正しているのか、情報を補足しているのか、それとも名前を変更しているのかを確認します。
2.  **特定 (再取得)**: 修正対象の記憶を見つけます（ID を渡していれば、この手順は省けます）。
3.  **照合 (比較)**: LLM に新旧の情報を注意深く比較させ、完全な追加 (ADD) なのか、更新 (UPDATE) が必要なのかを判定します。
4.  **リスク制御 (安全チェック)**: LLM が勝手に改変しないようにします。たとえば ID は正しいか？長い文書を丸ごと削除しようとしていないか？（しきい値によるブロックがあります）。
5.  **出版 (書き込み)**: 最後にグラフデータベース操作を実行し、古いものをアーカイブし、新しいものを書き込みます。

## 6. 開発例

ここに実行可能なコード一覧があり、サービスを初期化し、「誤った記憶」を事前配置し、その後ユーザーフィードバックによってそれを修正する方法を示します。

### 6.1 準備作業

まず、`SimpleMemFeedback` サービスを初期化する必要があります。

```python
# llm, embedder, graph_db などのコンポーネントは Factory によって初期化済みであると仮定します
# 完全な初期化コードは examples/mem_feedback/example_feedback.py を参照してください

from memos.mem_feedback.simple_feedback import SimpleMemFeedback

feedback_server = SimpleMemFeedback(
    llm=llm,
    embedder=embedder,
    graph_store=graph_db,
    memory_manager=memory_manager,
    mem_reader=mem_reader,
    searcher=searcher,
    reranker=mem_reranker,
    pref_mem=None,
)
```

### 6.2 シナリオのシミュレーションとフィードバックの実行

シナリオ：システムが誤って「あなたはリンゴが好きで、バナナは好きではない」と記憶してしまいました。今からこれを修正します。

```python
import json
from memos.mem_feedback.utils import make_mem_item

# 1. 対話履歴をシミュレーション
# ユーザーが嗜好を尋ね、アシスタントが間違って答えた
history = [
    {"role": "user", "content": "私はどんな果物が好きで、どんな果物が嫌いですか"},
    {"role": "assistant", "content": "あなたはリンゴが好きで、バナナは好きではありません"},
]

# 2. 「誤った記憶」を事前配置
# 手動で誤った事実を 1 件ストアに入れる
mem_text = "あなたはリンゴが好きで、バナナは好きではありません"
# ... (make_mem_item の詳細パラメータは省略、ソースコード参照) ...
memory_manager.add([make_mem_item(mem_text, ...)], ...)

# 3. ユーザーフィードバック
feedback_content = "間違っています、実際には私が好きなのはマンゴスチンです"
print(f"Feedback Input: {feedback_content}")

# 4. 修正を実行
# MemFeedback は衝突を検出し、古い記憶をアーカイブして、新しい記憶「マンゴスチンが好き」を書き込みます
res = feedback_server.process_feedback(
    ...,
    chat_history=history,
    feedback_content=feedback_content,
    ...
)

# 5. 結果を確認
print(json.dumps(res, indent=4))
```

## 7. 設定説明

MemFeedback を動作させるには、以下のコンポーネントの設定を準備する必要があります（通常は `.env` または YAML 内）：

*   **LLM (`extractor_llm`)**: 頭の良さが必要で、GPT-4o レベルのモデルを推奨します。Temperature は低め（たとえば 0）に設定してください。これは論理分析を行うためであり、あまり発散する必要はありません。
*   **Embedder (`embedder`)**: 新しい記憶をベクトルに変換するために使用します。
*   **GraphDB (`graph_db`)**: 記憶をどこに保存し、どのように保存するかは、この 2 つが担当します。
*   **MemReader (`mem_reader`)**: 純粋な追加の記憶である場合、それを解析するために使用します。
