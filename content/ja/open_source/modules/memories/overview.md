# なぜ異なるメモリモジュールが必要なのか

メモリモジュールは、Agent に「長期記憶」能力を与える中核コンポーネントです。これはデータベースのように機械的にデータを保存・取得するだけではなく、人間のように情報を自動的に抽出、分類、関連付け、動的に更新できます。異なるメモリモジュールを選択することで、Agent に異なる能力を持たせることができます。

## 🎯 クイック選択ガイド

::alert{type="info"}
**どれを選べばよいかわからない？** この決定木に従ってください：
- 🚀 **迅速なテスト/デモ：簡単に始められ、追加ソフトウェア不要** → [NaiveTextMemory](#naivetextmemory-簡単なプレーンテキストメモリ)
- 📝 **汎用テキストメモリ：チャット内容や大量のドキュメントを記憶し、意味に基づいて検索可能** → [GeneralTextMemory](#generaltextmemory-汎用テキストメモリ)
- 👤 **ユーザー嗜好管理：ユーザープロファイル向けに特化して設計** → [PreferenceTextMemory](#preferencetextmemory-嗜好メモリ)
- 🌳 **構造化知識グラフ：データ間に複雑な論理的関連がある** → [TreeTextMemory](#treetextmemory-階層構造メモリ)
- ⚡ **推論高速化：アクセス量が非常に多く、応答をより安定させ、応答速度を高めたい** → [KVCacheMemory](#kvcachememory-アクティベーションメモリ)
::

## 📚 メモリモジュール分類

### 一、テキストメモリシリーズ

テキスト形式のメモリの保存と検索に特化しており、ほとんどのアプリケーションシナリオに適しています。

#### NaiveTextMemory: 簡単なプレーンテキストメモリ
::card
**適用シナリオ：** 迅速なプロトタイピング、デモ、教育、小規模アプリケーション

**中核機能：**
- ✅ 依存関係ゼロ、純粋なメモリ保存
- ✅ キーワードマッチング検索
- ✅ 極めてシンプルな API、5 分で開始可能
- ✅ ファイル永続化をサポート

**制限事項：**
- ❌ ベクトル意味検索なし
- ❌ 大規模データには不向き
- ❌ 検索精度に限界あり

📖 [ドキュメントを見る](./naive_textual_memory)
::

#### GeneralTextMemory: 汎用テキストメモリ
::card
**適用シナリオ：** 会話エージェント、個人アシスタント、知識管理システム

**中核機能：**
- ✅ ベクトルベースの意味検索
- ✅ 豊富なメタデータサポート（タイプ、時間、ソースなど）
- ✅ 柔軟なフィルタリングとクエリ
- ✅ 中〜大規模アプリケーションに適する

**技術要件：**
- ベクトルデータベース（Qdrant など）が必要
- Embedding モデルが必要

📖 [ドキュメントを見る](./general_textual_memory)
::

#### PreferenceTextMemory: 嗜好メモリ
::card
**適用シナリオ：** パーソナライズ推薦、ユーザープロファイル、スマートアシスタント

**中核機能：**
- ✅ 明示的および暗黙的嗜好を自動認識
- ✅ 嗜好の重複排除と競合検出
- ✅ 嗜好タイプ、強度によるフィルタリング
- ✅ ベクトル意味検索

**専用機能：**
- 二重嗜好抽出（explicit/implicit）
- 嗜好強度スコアリング
- 時間減衰サポート

📖 [ドキュメントを見る](./preference_textual_memory)
::

#### TreeTextMemory: 階層構造メモリ
::card
**適用シナリオ：** 知識グラフ、複雑な関係推論、マルチホップクエリ

**中核機能：**
- ✅ グラフデータベースベースの構造化保存
- ✅ 階層関係と因果連鎖をサポート
- ✅ マルチホップ推論能力
- ✅ 重複排除、競合検出、メモリスケジューリング

**高度な機能：**
- MultiModal Reader をサポート（画像、URL、ファイル）
- インターネット検索をサポート（BochaAI、Google、Bing）
- ワーキングメモリ置換メカニズム

**技術要件：**
- グラフデータベース（Neo4j など）が必要
- ベクトルデータベースと Embedding モデルが必要

📖 [ドキュメントを見る](./tree_textual_memory)
::

### 二、専用メモリモジュール

特定のシナリオ向けに最適化されたメモリシステム。

#### KVCacheMemory: アクティベーションメモリ
::card
**適用シナリオ：** LLM 推論高速化、高頻度の背景知識再利用

**中核機能：**
- ⚡ KV Cache を事前計算し、重複エンコードをスキップ
- ⚡ プレフィル段階の計算を大幅削減
- ⚡ 高スループットシナリオに適する

**典型的なユースケース：**
- よくある質問（FAQ）キャッシュ
- 対話履歴の再利用
- ドメイン知識の事前ロード

**動作原理：**
安定したテキストメモリ → KV Cache に事前変換 → 推論時に直接注入

📖 [ドキュメントを見る](./kv_cache_memory)
::

#### ParametricMemory: パラメトリックメモリ
::card
**状態：** 🚧 開発中

**設計目標：**
- 知識をモデル重み（LoRA、エキスパートモジュール）にエンコード
- 能力モジュールを動的にロード/アンロード
- マルチタスク・マルチロールアーキテクチャをサポート

**将来の機能：**
- パラメータモジュールの生成と圧縮
- バージョン管理とロールバック
- ホットプラグ対応の能力モジュール

📖 [ドキュメントを表示](./parametric_memory)
::

## 🛠️ ユースケース推奨

### シナリオ 1: 高速プロトタイプ開発
**推奨：** [NaiveTextMemory](./naive_textual_memory)
```python
from memos.memories import NaiveTextMemory
memory = NaiveTextMemory()
memory.add("ユーザーはコーヒーを飲むのが好き")
results = memory.search("コーヒー")
```

### シナリオ 2: チャットボットメモリ
**推奨：** [GeneralTextMemory](./general_textual_memory)
- セマンティック検索をサポート
- 時間、タイプ、ソースでフィルタリング
- 対話履歴管理に適する

### シナリオ 3: パーソナライズド推薦システム
**推奨：** [PreferenceTextMemory](./preference_textual_memory)
- ユーザーの好みを自動抽出
- 好みの競合検出
- 強度スコアリングとフィルタリング

### シナリオ 4: ナレッジグラフアプリケーション
**推奨：** [TreeTextMemory](./tree_textual_memory)
- マルチホップ関係クエリ
- 階層構造管理
- 複雑な推論シナリオ

### シナリオ 5: 高性能 LLM サービス
**推奨：** [KVCacheMemory](./kv_cache_memory)
- FAQ システム
- カスタマーサポートボット
- 大量リクエスト処理
